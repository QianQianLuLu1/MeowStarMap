## 1. 上游数据契约（实采结论，经上游源码逐字核实）

1. **数据位置**：`NormalPhotoInfo` 与 `MultiPlayerHandler` 都在解密 JSON **顶层**（`social_photo` 的兄弟键，PascalCase）；旧照片整键缺失。`parseCameraParams`（数组位段 0–30）本阶段零改动。
2. **字段契约**（`rust/src/nuan5_params/nuan5_structs/image_custom_data.rs`）：
   - `NormalPhotoInfo`：`PhotoMode`/`WindIntensity`/`WindDirection` 均为容器内必填 i8；容器本身可缺（`skip_serializing_if`）。
   - `MultiPlayerHandler`：`RoleID`(i64 必填)、`PoseID`/`PosePlayingPercent` 为 **OptionValue——空串 `""` 表示"存在但无值"**（v3.012.01 修复 f86a2b2：给 OptionValue 反序列化补 `#[serde(untagged)]`，修复前联机照片整体解析失败）；`LocalPoseID`/`LocalPlayType`/`OtherPlayType`/`LocalTransforms` 上游解析后丢弃。
   - 上游 converter（`converter.rs` `convert_multi_player_params`）只保留 `roleId`/`poseId`/`posePlayingPercent` 三字段；`photoMode`/`windIntensity`/`windDirection` = `normal_photo_info.map(|i| i.<field>)`（容器缺 → None）。
3. **取值范围**（上游打包语言包 `assets/lang/infinity_nikki/zh-CN.json`，MIT）：
   - 拍照模式（上游 UI 标签"相机模式"）：`0=普通拍照, 1=定格瞬间, 2=双人合拍, 3=游戏截图`
   - 风力：`-1=未知, 0=无风, 1=小风, 2=中风, 3=大风, 4=特大风` —— **0 是真实值，不得折叠为空**
   - 风向：`-1=未知, 0=东, 1=南, 2=西, 3=北, 4=东南, 5=西南, 6=东北, 7=西北, 8=无`
4. **上游展示行为**（`tree_node_generator.dart`）：拍摄信息组内"相机模式/风力/风向"三行，枚举值经语言包分类映射、缺 key 回退原始数字；"联机信息"组只显示"另一位玩家的动作"（nikki_pose 名，语言包无此分类时回退原始 ID）+ 子行"进度"=`(p*100).ceil()%`（仅 percent 非 null 时）；**`RoleID` 解析但不上 UI**（用户已确认对齐此行为，DTO 仍保留 roleId）。

## 2. 空值三态语义（本阶段核心要求）

| 数据形态                                  | 解析结果                                   | 展示       |
| ----------------------------------------- | ------------------------------------------ | ---------- |
| 顶层键不存在（旧照片/单人照）             | `null`                                     | 行/组隐藏  |
| 键存在但值为空串 `""`（OptionValue None） | `null`（**不得**经 `Number('')` 折叠为 0） | 行隐藏     |
| 键存在且为数值 `0`（真实零值，如无风）    | `0`                                        | 显示"无风" |

实现载体：新增 `numOrNull(v)`：有限 number → 原值；非空数字字符串 → `Number(v)`；其余（undefined/null/`""`/非数字串/NaN）→ `null`。现有 `num()` 恒返回 number，禁止用于新字段。

## 4. 错误处理与参数校验

- 外部数据不可信：容器与字段全部走 `pick` 三变体（snake→camel→Pascal）+ `numOrNull` + 对象形态校验；非法形态 fail-soft 为 null，不抛裸错误。
- 解析器独立 try-catch（与既有 parsePhotographyInfo 等并列），单点失败不拖垮其余参数组。
- 枚举未知值：映射 miss → `detail.*.typeValue` 模板 / `#ID` 兜底，无 undefined/null 字样呈现。
- 无新增 IPC / 无新增外部输入面（既有 `decrypt:decodeFile` 通道透传）。
