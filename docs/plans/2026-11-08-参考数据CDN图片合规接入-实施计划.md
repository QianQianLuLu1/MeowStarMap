## 1. 前提核实结论

**参考数据管道已具备，本阶段只消费、不改其契约。**

- `getNetworkImageTemplates()` 返回 10 类 `{ kind, baseUrl, replace }`（`NetworkImageTemplateInfo`）。
- 地址生成规则（`docs/IPC_CONTRACT.md` + proto 注释确认）：`baseUrl.replaceAll(replace, String(id))`。
- 10 类 kind：`light` / `filter` / `momoPose` / `cloth` / `clothOutfit` / `diyPattern` / `clothType` / `clothProp` / `clothTag` / `nikkiPose`。

**尚未实现（= 本阶段工作面）**：地址生成函数、按主机授权核实、图片应用层缓存、按主机区分的请求标识、退避与占位回退、加速入口设置项、展示场景接入。

## 3. 架构决策（技术选型声明）

1. **主进程取图 + 磁盘缓存 + 复用 `media://` 供图。** 「应用层缓存」是硬要求，浏览器 `Cache-Control` 不可控且无法做损坏恢复/负缓存，故取图收敛到主进程；渲染层只引用 `media://file?path=<缓存文件>`，**永不直连 nikkialbums**。
2. **两套 UA 规则天然分离、不混用。** nikkialbums 的 `MeowStarMap/<版本>` 由主进程 fetch 请求头携带（与 `reference-data-service.fetchBytes` 同款写法）；gongeo 的固定串仍由 `cdn-user-agent.ts` 的 webRequest 拦截负责。**`cdn-user-agent.ts` 与 CSP `img-src` 均不改动**——渲染层不直连新主机，`media:` 已在 `img-src` 白名单内。
3. **按主机授权注册表**（`reference-data/image-url.ts`）：`cdn.nikkialbums.com → 接入（版本化 UA）`、`cdn.gongeo.us → 不经新路径（返回 null，继续走既有衣橱热链）`、未知主机 → `null`（默认不接入）。运行时按 **resolved URL 的实际 host** 核实，对 v1.db 数据漂移鲁棒（而非按 kind 硬编码信任）。
4. **供图复用既有 `?path=` 路由**：仅在 `isMediaPathAllowed` 增 1 条「参考图片缓存目录」规则（与缩略图目录规则同构，均为 app 受控目录），复用现成的 Range / ETag / mime / realpath 服务逻辑，不新起协议分支。
5. **加速/镜像独立设置键** `referenceData.imageMirrorBaseUrl`（与 manifest 镜像键分离，语义不同不可复用）；配置后仅替换**已授权**资源的取图 host，path/query 原样保留；应用不内置、不代建节点、不二次分发。
6. **零新依赖**：`protobufjs` / `fetch` / `node:crypto` / `fs` 均已在用；磁盘缓存复用 `cloth-diy-cache.ts` 的 sha256 命名范式与 `atomic-file.ts` 的原子写。

## 5. 错误处理与参数校验（贯穿各子任务）

- **主机**：授权注册表按 hostname 精确匹配；未知主机 → 不接入（`null`）。用户输入的 mirror 经 `assertSafeRemoteUrl`（拒环回 / 私网 / 保留段 / 非 http(s)）。
- **地址与空值**：`kind` 必须属于 `NETWORK_IMAGE_KINDS`；`id` 必须为正安全整数；templates 为空、`baseUrl` 非法 URL、`replace` 为空串 → 一律 `null`（渲染层回退占位）。
- **边界**：`replaceAll` 全量替换（占位串多次出现）；id 位数越界不截断；mirror 尾部斜杠归一；缓存 key = `sha256(kind:id)`，无路径穿越面。
- **失败语义**：HTTP 404 → 负缓存（短 TTL，防重试风暴）；网络错误 / 5xx → per-key 冷却退避（5 分钟量级，对齐 `cloth-data-config`）；缓存文件损坏（0 字节 / 非图片魔数）→ 删除后重取一次；**全部 fail-soft**——查询永不抛错，渲染层占位，不影响其余行与其余功能。

## 6. 测试计划（正常 / 异常 / 边界三类）

与源码同目录 Vitest 套件，每个新增/修改文件配套：

- **正常**：8 类地址生成、缓存命中零网络、过期重取、mirror 生效、缩略图渲染。
- **异常**：404 负缓存、网络失败冷却、损坏文件自愈、SSRF mirror 拒绝、非法 kind/id、`onError` 占位。
- **边界**：`replaceAll` 多次出现、id 上下界、mirror 尾斜杠、空 templates、`InfoRow` 无 image 字段的既有面板。

核心红→绿顺序：T2 先写「命中缓存零网络」「404 不重试风暴」「UA = `MeowStarMap/<版本>`」「损坏重取」四条失败用例，再实现。

**零新启动步骤。** 图片服务纯按需（IPC 触发），无后台定时器，故不改 `lifecycle.ts` / `cleanup.ts`。缓存目录首次写入时惰性创建。

## 8. 验证工作流（scoped，遵「只跑本次涉及文件」）

- 每步：`npx vitest run <本次测试文件>` + `npx eslint <本次文件>` + `npx prettier --check <本次文件>`。
- 类型：`npx tsc -b`（工程级，无法只跑单文件）——若报错落在**本阶段未触碰的 WIP 文件**，如实上报、不代修。
- **不跑** `npm run verify` / 全量 `npm test`：其 `git diff HEAD` 会卷入仓库中未提交的阶段 2/3 WIP，违背 scoped 约定。
- 受保护路径（`services/**`、`ipc/handlers/**`、`preload/api/**`）的改动同批携带/替换唯一 `@core-change:` 真实中文原因，过核心闸门。
