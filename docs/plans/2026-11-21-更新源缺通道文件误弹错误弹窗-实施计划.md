# 实施计划：更新源缺通道文件误弹「未获取到可用的更新信息」错误弹窗（根因修复）

- 日期：2026-11-21
- 轮次目标：设置 › 应用信息与联系方式 › 检查更新，在网络可访问 GitHub 的前提下仍弹出「未获取到可用的更新信息，点击确定跳转官网」错误弹窗的根因分析与修复。
- 需求口径（用户确认）：发布源没有比当前更新的版本时，应显示「当前已是最新版本」而不是误导性错误弹窗；确有更新版本但元数据缺失时维持错误弹窗。
- 改动约束：仅改主进程错误决策面（2 个源文件 + 2 个测试文件 + 1 个契约注释 + 1 个 CI 加固 + CHANGELOG + 本计划）；渲染层 / IPC / i18n / preload / 打包脚本零改动；零新增依赖；严格红灯→绿灯。

## 一、根因分析（Context）

**现象**：GitHub 完全可达时，检查更新必弹错误弹窗。

**取证（2026-11-21 本机实测 api.github.com）**：

1. 仓库唯一正式 Release：tag `MeowStarMap-Setup-2.5.6`（2026-11-04 手工发布，`prerelease:false`），资产**只有 `MeowStarMap-Setup-2.5.6.exe`，没有 `latest.yml`**。
2. 本地已构建 2.5.7（`release/MeowStarMap-Setup-2.5.7.exe` + `latest.yml`，同日 17:15），但**从未推 `v*` tag、从未发布到 GitHub Releases**（本地 git tags 无 v2.5.7，远端 `/releases/latest` 仍指向 2.5.6）。
3. electron-updater 6.8.9（`allowPrerelease=false`，`auto-update.ts:85`）固定请求 `releases/download/<latest-tag>/latest.yml` → **404** → 抛 `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND`（`GitHubProvider.js` fetchData catch）→ `classifyUpdateError`（`update-error-class.ts:145`）按 4xx 归 `source` → `UpdateDialog.tsx:255-257` 渲染 `settings.about.updateSourceUnavailable` 弹窗。**100% 确定性复现，与网络可达性无关**。

此结论与仓库既有取证一致（`scripts/pre-dist-check.ts:481-485`、`docs/plans/2026-11-05-fix-update-check-network-busy-misreport.md`）。2026-11-21 上午的「传输信号补口」轮修复的是网络失败被误归 source 的三类缺口，不覆盖本根因（channel 文件真 404 属发布侧问题，归类 `source` 按契约是正确的——错的是「明明没有更新版本却弹错误弹窗」的呈现层决策）。

**修复方向**：electron-updater 抛的 `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND` 错误 message 内嵌 channel URL（`.../releases/download/<tag>/latest.yml`，generic 假源形态则为 `http://127.0.0.1:8123/latest.yml` 无 tag）。从 tag 提取版本并与当前版本比较：

- tag 版本 ≤ 当前版本 ⇒ 发布源没有可用的新版本 ⇒ 主进程改推 `{stage:'not-available', version}`，渲染层复用既有「当前已是最新版本」视图（`UpdateDialog.tsx:278-312`，零渲染层改动）。
- tag 版本 > 当前版本 ⇒ 确有更新但元数据缺失 ⇒ 维持 `{stage:'error', errorKind:'source'}`。
- 提取失败 / 版本不可解析 / 非 `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND` 错误 ⇒ 一律维持现有归类与弹窗（保守兜底）。

**版本比较实现取舍**：自研 ~15 行纯函数（提取 `X.Y.Z` 数字三元组逐段比较，无三元组即回退错误弹窗），不引入 semver 依赖——semver@6.3.1 虽在依赖树中但未声明、且 @types/semver@6 断代；真实更新决策仍由 electron-updater 的 semver 负责，本函数只决定弹窗文案，保守失败。

## 四、错误处理（异常分支、兜底、日志）

- `missingChannelUpToDateVersion(err, currentVersion)` 沿用模块「永不抛错」契约：入参 unknown（Error / 字符串 / null / Proxy / throwing getter）全部经既有 `safeGet` / `asRecord` / `causeChain` 收窄；提取失败、版本不可解析一律返回 null 回退错误弹窗。
- 转换仅命中 `ERR_UPDATER_CHANNEL_FILE_NOT_FOUND` 且 tag 版本可解析且 ≤ 当前版本；generic 形态 URL 无 tag → 维持 source 错误。
- 三个推送点（error 事件 `auto-update.ts:142-155`、checkForUpdates catch `:185-188`、downloadUpdate catch `:209-214`）统一走新私有 `buildErrorPayload(err)`；F8 事件归属 / 单次推送记账逻辑不动。
- 日志：转换命中时打 `[Update] missing channel file → not-available vX.Y.Z (≤ current)`（纯字面量，与既有 `[Update]` 前缀日志同风格，不动 i18n）。

## 五、参数校验

- 入参：`err: unknown`（不校验类型、不抛错）；`currentVersion: string`（`app.getVersion()`）。
- tag 提取正则 `/\/download\/([^/]+)\/latest[^/]*\.yml/i`；版本三元组 `/(\d+)\.(\d+)\.(\d+)/` 首个匹配、缺失段补 0；任一步失败返回 null。
- 边界：cause 链深度仍 `MAX_CAUSE_DEPTH=8` 封顶、seen 集合挡循环（既有）；`2.5.7-beta` 等预发布段按基础三元组比较。

## 六、基础测试用例

- 正常场景：tag `MeowStarMap-Setup-2.5.6`（线上真实形态）+ 当前 2.5.7 ⇒ 返回 '2.5.6'（→ not-available）；版本相等 ⇒ 同。
- 异常场景：tag `9.9.9` > 当前 ⇒ null（维持 source 错误）；非缺失通道错误（INVALID_RELEASE_FEED / ECONNREFUSED / timeout）⇒ null；集成面：`emit('error', …)` 推 `{stage:'not-available', version}`；新版缺失仍推 `{stage:'error', errorKind:'source'}`。
- 边界场景：`v2.5.7` 形态 ⇒ '2.5.7'；tag 无数字三元组（`nightly`）⇒ null；字符串 / null 入参 ⇒ null；cause 链内嵌错误仍可提取；既有「error 只推一次」「F8 并发交错」锁保持绿。
