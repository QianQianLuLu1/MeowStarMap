# 实施计划：审查修复轮 + 2.5.7 正式版发版（2026-11-21）

> 范围：对 `bed034ac`（MeowStarMap-Setup-2.5.6）之后全部未发布提交与工作区未提交改动做全面审查，
> 修复确认缺陷后六项验证全绿，提交、升版 2.5.7、重打包。
> 上游审查依据：三路并行探索审查（取证日志体系 / log-export / glass-lite / scanner 看门狗 + 两摊在途改动），报告要点已并入本计划。

## 一、依赖声明

- **零新增运行时/开发依赖**。全部修复复用仓库现有设施：Vitest（既有配置）、`performance.now`（Node 原生）、既有 AppError / manifest.missing 模式。
- 版本变更：`package.json` `version` 由 `2.5.7-beta` → `2.5.7`（经 `npm version 2.5.7 --no-git-tag-version`，同步 lock 根与 `packages[""]`），无其他依赖树变更。

## 二、启动与运行说明

- 环境要求：Node ≥22.12、Windows x64、`node_modules` 已装（`.bin` 下 vitest/electron-vite/playwright/tsc/tsx 齐备）。
- 验证命令链（顺序执行，全部要求 exit 0）：
  1. `npm install`（若剪除 `@nikkisync` junction：`npm run link:nikkisync` + `npm run verify:nikkisync`，blocking 须 0）
  2. `npm run build`
  3. `npm run test`
  4. `npm run typecheck`
  5. `npm run e2e:smoke`（基线轮用现有 2.5.7-beta 打包产物；终版轮在 `npm run dist:win` 产出 2.5.7 产物后复跑）
  6. `npm run test:ci-linux`
  7. 发版轮：`npm run dist:win`（内含 build + pre-dist-check 三闸门 + electron-builder + verify:dist）
- 功能验证方法：每项修复以「修复前红灯 → 修复后绿灯」的单测读数为准；终版以 e2e:smoke 24 用例 + verify:dist 全项通过为准。

## 三、错误处理

- 六项验证任一失败：TDD 定位根因（先写可复现红灯测试），修复后重跑；禁止跳过/弱化断言。
- 打包三闸门（`check-changelog-release` / `check-doc-versions` / `pre-dist-check`）失败即阻断：按报错修正源面（CHANGELOG 收口、版本声明同步），不改闸门脚本。
- 打包 EBUSY：按仓库先例排查持锁进程；必要时改道打包目录后移回产物。
- 提交钩子（lint-staged + tsc -b + commitlint）拦截：修正信息/格式后重提，不绕过钩子。
- 核心路径闸门：本轮触及 `src/main/services/log-service.ts`、`src/main/ipc/handlers/settings-handler.ts`，文件顶部前 5 行补 `// @core-change: <真实原因>`（替换旧值，至多一条）。

## 四、参数校验（修复项自身的输入约束）

- F1 崩溃对话框：`dialog.showMessageBox` 的 parent 已判 `isDestroyed`；新增兜底覆盖「await 期间销毁 / showMessageBox 本身 reject」两类异常分支。
- F2 manifest 登记：`missing` 条目复用既有 `{path, reason}` 结构；reason 取值与 chromium/diag 节一致（`readdir-failed`/`copy-failed` 类），不得引入新枚举形状。
- F3 设置留痕：留痕仅在「校验通过且 `setSetting` 成功」后执行；`fmt` 截断阈值维持 1024 字符，oldValue 读取失败 fail-open（不阻断写入）。
- F4 看门狗：静默时长度量由 `Date.now()` 切 `performance.now()`（同一取时函数贯穿 lastMessage 记录与 tick 计算）；宽限窗口与杀链阈值（15s 嫌疑 / 10s 宽限）数值不变。
