## 2. 关键设计决策

- **D1 值名 vs 回读冲突（已查证）**：`getLoginItemSettings(options)` 的 options **没有 `name`**。若给主路径显式传 `name`，回读将读不到同一项，设计自相矛盾。故：**主路径永远不传 `name`**（与 `getLoginItemSettings()` 默认 AUMID 名严格一致）；历史旧名用 `setLoginItemSettings({ openAtLogin:false, name:<旧名> })` 单独清理，不参与回读。
- **D2 清理名单来源**：完全来自 T0 现场 `reg query` 输出 + 用户人工确认，写成 `login-item.ts` 模块级常量 `LEGACY_LOGIN_ITEM_NAMES: readonly string[]`。**取证确认前保持空数组（不清理任何项，避免误删第三方启动项）**；若最终确认名单为空，则如实记录「现场无历史残留项」，不得伪造清理效果。为可测，导出纯函数 `cleanupLegacyLoginItemNames(names)`，单测直接传 `['old-name']`。清理在打包态每次 `syncLoginItemSetting` 成功后执行（覆盖开关写入与启动期两条路径）；dev 态门控提前 return，完全不触碰 OS。单项独立 try/catch，失败记 `diagLog` + `logger.warn`，不阻断主设置但**日志可核对**。
- **D3 失败传播**：**失败抛 `AppError.internal(..., { userMessage })`**（系统 API 抛错 / 回读不一致 / 回读非布尔），由 `wrapHandler` → `IpcError` → 渲染层既有 `catch` 回滚 + error toast。零新增结构、复用全仓统一错误链路。**非失败的跳过**（dev）不抛错，返回 `synced:false, skipped:'dev'`。不改用「返回 `synced:false` 由每个调用点自查」——那正是「无条件成功 toast」同类缺陷的复发条件。`settings:set` 成功返回体扩展为向后兼容的可选字段 `{ saved:boolean; synced?:boolean; skipped?:'dev' }`，`saved` 语义与其它分支一致，不新增通道、不改方法名、不改 `electronAPI` 键集合。
- **D4 DB 一致性**：handler 先读 `previous = getSetting(key, default)`，再 `setSetting(key, value)`，再同步；同步抛错时先 `setSetting(key, previous)` 回滚 DB 再原样 throw，避免「UI 回滚但 DB 已是新值、下次启动又把失败意图写回」。
- **D5 dev 门控「调整」**：保留 `app.isPackaged !== true` **不写 OS** 的护栏（避免把 `electron.exe` 写进 Run 项），但不再谎报成功——返回 `{saved:true, synced:false, skipped:'dev'}`，渲染层给专门提示 `toast.launchAtLoginDevSkipped`（「开发模式不写系统登录项，设置已保存」），**不显示** `launchAtLoginOn/Off` 成功 toast。
- **D6 启动期比对**：新增 `readLoginItemOpenAtLogin(): boolean | undefined`（dev 返回 `undefined` 不触碰 OS；打包态调 `getLoginItemSettings()`，仅采信布尔值，异常/非布尔返回 `undefined` 并记日志）。`lifecycle.ts` 阶段 8 先比对：`os === openAtLogin` → 只记 `unchanged, skip write` 不写；不一致或读失败 → 保守照常同步。保留外层 try/catch「失败不阻塞启动 + `logStartupError` 留痕」。**残留限制如实记录**：`getLoginItemSettings().openAtLogin` 不反映 `StartupApproved` 的 OS 手动禁用（`executableWillLaunchAtLogin` 才反映）；启动期永远以 DB 为真相做幂等同步，**不引入「用户是否显式设置过」标记**（避免投机设计）。
- **D7 常量层级与范围收敛**：在 `ROOT/src/shared/settings-keys.ts` 新增 `SETTING_KEY_LAUNCH_AT_LOGIN`（`as const`）、`LAUNCH_AT_LOGIN_DEFAULT`、`normalizeLaunchAtLoginSetting()`，白名单数组元素改用常量（渲染层不 import `src/main`）。`login-item.ts` 保留原有三个导出名改为从 shared re-export，保证 `lifecycle.ts:36` 与 `login-item.test.ts` 既有 import 不断裂。**评估后不改**：`shared.tsx` 的 `SettingsToggle`（改它波及全部设置开关，而本开关失败路径是 async，已由 `saveLaunchAtLogin` catch 与 IPC 层覆盖）、`connection.ts:2032` 的 `setSetting` `!this.db` no-op（波及所有设置写入，设置页不可达该窗口）、`preload/ipc.ts`、`app-error.ts`、`ipc.ts`、`index.ts`、`package.json`。
- **D8 契约与治理**：改 `settings-handler.ts` 与 `preload/api/settings.ts` 会触发 CI「IPC contract sync check」（`.github/workflows/build.yml:93-105`），`docs/IPC_CONTRACT.md` **必须同批进 diff**；两个受保护文件顶部前 5 行内须各放**至多一条**本次真实中文原因的 `// @core-change:`（`settings-handler.ts:1` 现有注释需替换，旧原因不复用）；`ipcMain.handle` 第二参仍为 `wrapHandler`，禁裸 `throw new Error()`。

## 8. 已知限制与风险（如实列全）

1. **dev 态不写 OS**：`app.isPackaged !== true` 护栏保留，`skipped:'dev'` 仅为不谎报成功，不能用于验证真机行为。
2. **StartupApproved / OS 手动禁用**：`Settings.enabled`（`electron.d.ts:23073-23078`）与任务管理器禁用态不在 `getLoginItemSettings().openAtLogin` 中体现，回读发现不了；`executableWillLaunchAtLogin` 才反映停用态，本期不引入该判断（避免投机设计）。
