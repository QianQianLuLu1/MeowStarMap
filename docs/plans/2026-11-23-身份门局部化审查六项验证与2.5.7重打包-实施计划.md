## 11. 执行后记（2026-11-23，TDD 红-绿闭环）

### 11.1 验证中新发现的缺陷（计划外、必须修复）

首次 `npm test` 全部断言通过（552 files / 8968 passed / 20 skipped），但**退出码 1**：Node 26 报 7 次 `FileHandle object was closed during garbage collection`（`scan-diagnose.test.ts`）。根因链：

1. `exifr` 7 的 `Exifr.parse()` 仅在成功路径调用 `file.close()`；解析抛错时内部 `FileHandle` 不关闭。
2. Node 26 把「GC 回收未关闭 FileHandle」升级为未捕获异常（`ERR_INVALID_STATE`），进程退出码非 0。
3. 同一路径另有 68 次 `ERR_INVALID_ARG_TYPE`（exifr `open()` 内 `fh.stat(this.input)` 在 Node 26 严格校验下抛错）——正是「open 成功 → stat 抛错 → 未 close」的泄漏触发点。

Electron 41.10.6 内置 Node **24.18.0** 实测对 `fh.stat(string)` 兼容（`OK 12086`），产品运行时不受影响；本机 Node 26 属 `.node-version=22` 之外的开发环境。

### 11.2 修复（TDD）
