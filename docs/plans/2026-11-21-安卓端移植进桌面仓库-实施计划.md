# 安卓端移植进桌面仓库 · 实施计划书

> 状态：已批准（阶段 1/8 产出，2026-11-21）。执行进度见文末「执行记录」。

## 一、背景（Context）

喵星图（桌面仓 MeowStarMap，Electron+React+TS，v2.5.7）已内置 NikkiSync 协议 v1 服务端（运行时复用上游 @nikkisync/pc-companion 的 LocalSyncServer），README 声明「移动端可直接同步本机媒体库」，但桌面仓尚无自家移动端。上游作者 ToStardust 已明示同意将 NikkiSync/apps/mobile（纯 Java Android 工程，MIT）移植入本仓，条件：保留原 LICENSE 与版权声明；第三方游戏美术不在授权内；商店侧使用独立应用名/包名/签名/图标。本计划给出分段可执行路线：先红后绿、每段有可判定验收。

路径约定：仓库根 = `D:\项目\软件\MeowStarMap\MeowStarMap`（下文相对此根）；上游 = `..\NikkiSync\apps\mobile`，git 基线 commit `6bdab4b4b29b0af5103aafb2d3223e7903c6306c`（remote https://github.com/ToStardust/NikkiSync，detached HEAD）。

## 二、勘察结论（决定计划结构的硬事实）

**上游（..\NikkiSync\apps\mobile）**

- Gradle root 即 apps/mobile：Gradle 8.13 wrapper 已提交；AGP 8.7.3；纯 Java 无 Kotlin；compileSdk/minSdk/targetSdk=35/30/35；NDK 28.1.13356709 + CMake 3.22.1（native target `momo_jpeg`，CMake 下载 libjpeg-turbo 3.2.0 且 SHA256 pin）；applicationId 与 namespace 同为 `app.nikkisync.mobile`；versionCode 66 / versionName "1.0.40"（app/build.gradle.kts:21,24-25）；签名走环境变量 `MOMO_RELEASE_STORE_FILE/_STORE_PASSWORD/_KEY_ALIAS`，缺省时 release 不签名、preReleaseBuild 硬校验（:3-6,79-83）；`momoStoreSubmission=true` 切换 src/store/AndroidManifest.xml（移除自更新权限/组件）。
- 出树引用仅 3 处，全在 app/build.gradle.kts：:67 → `../../docs/store-submission`（4 份法务 md 进 APK assets/legal）；:71 → `../windows-shell/Assets/update-public-key.pem`（进 assets/updates）；:115 → `../../release/NikkiSync`（APK 改名输出）。
- 自更新：update/AndroidAppUpdate.java:19-20 硬编码 feed=cnb.cool 上游发布页；verifyPackage 要求同包名+同签名证书（:46-52）→ 换包名/新签名后上游 feed 必然失效。
- 源码内 `app.nikkisync.mobile` 硬编码均为 Java 包名全限定引用（namespace 面）；FileProvider authority 用 `${applicationId}.updates`、业务代码用 `getPackageName()` → 改 applicationId 影响面小。
- APK 内不含第三方游戏美术（res/assets 仅自绘图标、author_avatar.png、game-version-names.json 事实数据、license 文本）；游戏美术在仓库级 NikkiSync/assets/photo-filter-icons，不在拷贝范围。
- 测试：122 个 JVM 单测（JUnit4+Robolectric 4.17）+ 7 个 instrumented；CI 命令 `./gradlew testDebugUnitTest assembleDebug`。

**本仓（桌面）**

- electron-builder `files` 为白名单（package.json:228 起：dist/**、resources/**、LICENSE、THIRD_PARTY_NOTICES…）→ 新增顶层 mobile/ 不会进 asar；仍补 `"!mobile/**"` 防御。
- .gitignore / .prettierignore / eslint ignores 均未覆盖 mobile → 需补隔离。
- 可复用资产：LICENSE（MIT，Copyright (c) 2026 QianLu）；THIRD_PARTY_NOTICES（编号章节体例可续写）；resources/icons/icon-master.png + scripts/generate-icon.js（sharp 图标管线，仿写 Android 侧）；resources/nikkisync/pc/signing/update-public-key.pem（与上游 :71 引用同源，拷入前 sha256 对账）；docs/plans/「YYYY-MM-DD-名称-实施计划.md」体例；docs/sync-integration/ 协议文档。
- 桌面不注册 OS deep link：`nikki-sync://` 仅为二维码内容（src/shared/sync/protocol.ts:366-384）→ 移植无需动桌面协议面。
- CI 仅 build.yml，无 android job。

## 六、启动说明（命令 + 判定基线；每条亲自执行贴原始输出）

1. 桌面基线：`npm run lint && npm run typecheck && npm test` —— 基线：零失败（作为 mobile/ 加入后的回归对照）。
2. 环境探针：`java -version`（须 17.x）；`echo $ANDROID_HOME`；已装组件须含 `platforms;android-35`、`build-tools;35.0.1`、`ndk;28.1.13356709`、`cmake;3.22.1` —— 任一缺失即停，读数记入本文档。
3. Android 构建：`cd mobile && ./gradlew --version`（Gradle 8.13）`&& ./gradlew testDebugUnitTest assembleDebug` —— 基线：BUILD SUCCESSFUL、单测 0 失败（汇总行留痕）、产物 app/build/outputs/apk/debug/app-debug.apk。
4. 出包：`./gradlew stageDebugApk` —— 基线：根 release/MeowStarMap-Android.apk 生成。
5. 签名 release：设 `MOMO_RELEASE_STORE_FILE/_STORE_PASSWORD/_KEY_ALIAS=meowstarmap` 后 `./gradlew assembleRelease` —— 基线：BUILD SUCCESSFUL；`apksigner verify --print-certs` 显示新证书且 Verified。
6. 端到端：桌面 `npm run dev` → 开启同步服务（端口 28080、mDNS 开）→ 真机装 debug APK → 扫码/NSD 配对 → 浏览/保存 → 落盘 Pictures/NikkiSync 且 EXIF Model=MomoCamera；关开服务 WS 自动恢复；`adb shell am start -a android.intent.action.VIEW -d "nikki-sync://pair?…"` 唤起配对。

## 七、错误处理（场景/兜底/日志）

- Gradle 发行包/依赖下载失败：换网络或临时镜像（仅 wrapper distributionUrl，用后还原），输出原样留存；禁止离线 hack。
- SDK/NDK/CMake 缺失或版本不符：探针非零退出即停，补装重跑；不得跳过构建验证。
- libjpeg-turbo 下载失败/SHA256 不符：属预期防线，禁止绕过校验；换网重试并留日志。
- MOMO_RELEASE_* 未配置：preReleaseBuild 硬失败（保留上游机制）；禁止 debug 签名冒充 release 分发。
- freeze 守护漂移：立即停止后续阶段并回滚 offending 改动；禁止改预期值迁就代码。
- 桌面回归失败：停止移植提交先修复；不得弱化/删除断言。
- 真机配对失败：按 TLS 指纹 → 端口/防火墙 → mDNS 开关顺序排查；取证 adb logcat + %APPDATA%/meow-star-map/logs/main.log。
- 一切新增脚本：非法输入/缺文件 → 中文错误信息 + 非零退出；禁止静默失败。

## 八、参数校验

- applicationId：必须 `^[a-z][a-z0-9_]*(\.[a-z][a-z0-9_]*){1,}$`、无连字符/大写；定值 com.qianlu.meowstarmap；以 `aapt dump badging` 为最终判定。
- 构建属性：`momoStoreSubmission`、`meowSelfUpdate` ∈ {true,false}（require 校验，前者上游已有后者新增）；`MOMO_SUPPORT_URL` 无控制字符（上游已有）；`momoFilingNumber` 默认空。
- 签名三环境变量：release 必填且 keystore 文件存在（上游 check 保留）；keystore 与密码不入库、不出现在日志与文档。
- versionCode ≥1 整数、versionName 非空（定 67 / "1.0.41"）。
- 图标源 icon-master.png：必须存在且 ≥512×512 方图，否则脚本报错退出。
- legal 4 文件与 update-public-key.pem：Copy 源缺失即构建失败（上游行为保留）；pem 先 sha256 对账（与上游 apps/windows-shell/Assets/update-public-key.pem 一致才可采用，不一致即停报）。

**正常**：①上游 122 单测全绿；②assembleDebug/assembleRelease 成功；③QR 与 NSD 两条配对路径成功并可同步浏览；④保存原图字节一致（SHA-256 校验）且落盘 Pictures/NikkiSync；⑤adb deep link 唤起配对；⑥`NS1|` 紧凑串解析配对成功；⑦桌面 npm test/lint/typecheck/e2e:smoke 全绿。

1. ★包名不可回退：applicationId 上架后永不可改；上游 app.nikkisync.mobile 老用户无法覆盖升级，配对状态/本地库不迁移（数据在 /data/data/<旧包名>/）。缓解：包名已定稿；PORTING.md 与商店文案明示「独立应用，不迁移旧数据」。
2. ★签名密钥丢失不可恢复：新 keystore 丢失=已发布版本永远无法升级。缓解：仓库外双备份、记录 keytool 参数与别名、密码不入任何文档。
3. ★双源漂移：MeowStarMap/mobile 与上游 apps/mobile 各自演化成两份事实。缓解：PORTING.md 记基线 commit+remote；mobile:freeze 冻结守护；声明手工择优 backport 策略；桌面 protocol-contract.test.ts 继续守护桌面面。
4. ★自更新错源：沿用上游 feed/公钥会校验失败甚至误导分发。缓解：默认禁用（决策 3）；meowSelfUpdate=true 前必须同时换 feed+密钥对。
5. 协议冻结破坏（与桌面运行时上游 LocalSyncServer 断互通）：缓解：S2 守护网 + S5 端到端；EXIF/路由/键名逐条入表。
6. 桌面仓被污染：mobile/ 误入 asar、被 lint/format/CI 拖垮。缓解：files 白名单+`"!mobile/**"`+三处 ignore+CI 独立 job；S1/S6 双验收。
7. 法务缺口：漏保留上游 LICENSE/版权、legal 未替换旧应用名、未来误引入游戏美术。缓解：S1 LICENSE/S7 NOTICES/PORTING.md 红线；美术仅存在于未拷贝的仓库级 assets/。
8. 合规空缺：备案号/联系方式留空，商店提审前必须补齐（上架阶段 TODO）。
9. 环境不可用：JDK/SDK/NDK 本机可用性未实测 → S0 探针前置，缺即停。
10. CI 时长增长：android job 增加 runner 时长。缓解：独立 job 并行、缓存 gradle。
