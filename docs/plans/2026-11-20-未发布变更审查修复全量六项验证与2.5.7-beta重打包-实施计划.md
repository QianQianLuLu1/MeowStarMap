## 二、依赖声明

零新增依赖。本轮**必须**跑 `npm install`（用户硬性要求），而 npm 11 会剪掉 `node_modules/@nikkisync/*` 四条 junction（上游本地包链接）。处置顺序固定：

1. `npm install` → 2. `npm run link:nikkisync` → 3. `npm run verify:nikkisync`（要求 `ok×4`、`blocking 0`）→ 4. 之后再跑测试/构建。

`npm install` 后若 `link:nikkisync:check` 报缺，直接按上述 2→3 重链；不允许以 `--offline` 或删 lock 的方式绕过。

## 四、错误处理与兜底策略

- 修复一律以 `AppError` 家族表达可预期业务错误；`wrapHandler` 统一转 `IpcError`，不在 handler 内手写 `try/catch + return {success:false}`。
- 渲染层每个异步 effect 必须有 `alive` 门闩；`catch` 分支不得静默吞掉「有业务含义」的错误（保留上次成功值属允许的显式降级，须附注释说明为什么）。
- 定时器/监听器/`AbortController` 必须与 cleanup 成对出现；轮询必须在门控条件（视图可见 && 功能开关）关闭时清零。
- 日志：沿用既有 `logger` 分层，不新增 `console.log`。

## 五、参数校验

- IPC 入参一律经 `schemas`（zod）校验；新增/变更通道沿用 `z.tuple([schema.optional().default({})])` 口径。
- 新增 UI 入参（props）显式 `interface XxxProps`，禁止 `any`。
- 纯函数（如 `inspiration-filter.ts`、`organizer-states.ts`）对非法/未知枚举值必须返回「不命中」而非抛错。

## 七、基础测试用例（正常 / 异常 / 边界）

- 正常：五视图切换与持久化；配对二维码生成/倒计时/过期重生成；整理队列轮询与待批角标计数；灵感过滤五状态命中。

## 九、本轮用户裁决与冲突处置

1. **打包被第三方文件锁阻断**：`WorkBuddy.exe`（PID 23456）持有 `release\win-unpacked\resources\app.asar`，electron-builder 无法清理输出目录（EBUSY，200s 内 10 次探测均被锁）。Restart Manager 判定唯一持有者后请示用户，用户裁决「关闭该进程后继续」；该进程在处置过程中自行退出，锁随之释放，打包链路重跑成功。
2. **About 视图旧仓库外链 vs 产物禁串闸门**：`verify:dist` 扫 app.asar 命中 `github.com/<owner>/<本仓旧名>` 一处（来自上一轮新增的上游六链，台账原登记为「用户裁决上游 URL 不动」）。该闸门 fail-closed 无豁免通道，与本仓「安装包不得带旧仓库地址」的既有裁决直接冲突，故请示用户；用户裁决「删除该条外链」——`UPSTREAM_REPO_LINKS` 收敛为五链，台账删除该文件登记（hits 2）、`expectedTotal` 173→171，12 语包键保留（无消费点但键集仍须十二语对齐）。
