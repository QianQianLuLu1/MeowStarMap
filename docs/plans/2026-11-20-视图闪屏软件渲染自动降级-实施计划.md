# MeowStarMap「视图区域概率性闪屏」根因排查与修复计划

## Context（为什么做这次改动）

故障机（LAPTOP-QK36MA3G，i9-13980HX / RTX 4060 Laptop / 16GB / Win11 26100，应用 2.5.6）概率性出现**网格滚动时视图区域整块白闪/黑闪**（用户已确认形态与时机）。本机无法复现。日志包 `wxnn-logs-2026-11-19.zip` 取证结论：

**已证事实（日志包第一手证据）**

1. 故障机自 2026-10-28 起长期软件渲染；11-19 起 GPU 兼容档位 **level=2**（`--disable-gpu --disable-software-rasterizer`，纯 CPU 合成，GPU 进程结构性不启动）。
   - `gpu-fallback.json`：`{consecutiveFailures:0, fallbackActive:true, compatLevel:2, compatLevelVersion:"2.5.6"}`
   - `diag.log` 11-19 三次启动均有 `[INDEX] gpu compat level=2: --disable-gpu + --disable-software-rasterizer appended`
2. **用户手动关闭过「GPU 硬件加速」开关**（用户本轮确认）→ `gpu-pref.json` pref=false → 状态行 `hwAccel=off(user-disabled)`；pref=false 短路版本级重试（`gpu-fallback.ts:339`），机器被永久钉在软件渲染，直到用户重新开启。
3. 10-28 19:03（本地）首启还是 RTX 4060 硬件加速（`main.log:9`），16 秒后重启即软件渲染（`main.log:85-92`），当晚 4 次重启；11-19 02:29 旧格式二进制的会话被**原生层杀死**（`faults-2026-11-19.jsonl` exitDiagnosis：无 JS 退出痕迹，stage=initialized），02:32 新版启动检出 prevNativeKill → 阶梯升 level2（`gpu-fallback.ts:384`）。
4. 11-19 长会话中 **scanner worker 心跳超时自杀**（`main.log` 11:10:05 本地）：看门狗用 `Date.now()` 墙钟（`worker-entry.ts:1611`），笔记本睡眠/唤醒墙钟跳变 >15s 即误判父进程死亡——父进程实际存活（bridge 每 5s 无条件 ping，`scanner-worker-bridge.ts:178-189`）。
5. 11-19 **无**缩略图 404 / render-process-gone / GPU 崩溃记录；渲染层噪声仅 NikkiSync idle（已知噪声）、MaxListenersExceededWarning（11 个 scanner:complete 监听＝keep-alive 多实例合法并发，各订阅均有卸载清理）、每次启动搜索索引 indexed=0 重建（启动性能问题，与滚动闪屏无直接因果）。
6. 日志包缺 chromium-debug.log / heartbeat.json / last-exit.json / crashes/（manifest 列出但实缺，与 DEBT-049 诊断目录分叉登记一致）——帧级证据缺失，需真机补采。
7. 状态行 `v=?` 成因：pref=false 短路使 `fallbackVersion` 从未被盖戳（导出 json 无此字段）；`fails=1` 是启动计数期正常读数（8s settle 后清零，与导出 0 一致）。**「检测到 GPU 崩溃回退标记」日志在 user-disabled 时也打**（`index.ts` level≥1 即打该 i18n 文案）——误导取证，本轮修。

### 4. 参数校验

- `applyGlassMode(effect: string)`：仅 `'lite'` 触发用户档降级；其余值（含非法）按 rich；软件渲染标志为模块内布尔，无外部入参。

- `buildGpuCompatBootDiagLine(level: number, decision)`：level 由调用方传入已归一的 bootLevel（0/1/2）；reason 为共享类型枚举，模板拼接无注入面。
- N3：`HEARTBEAT_GRACE_MS` 正常量；`lastPingTime`/`suspectSince` 数值运算，无外部输入。

```js
  )
  if (!scroller) return console.log('NO_SCROLLER')
  const deltas = []
  let last = performance.now()
  let run = true
  const longtasks = []
  new PerformanceObserver((l) => longtasks.push(...l.getEntries().map((e) => e.duration))).observe({
    entryTypes: ['longtask']
  })
  let skel = 0
  new MutationObserver((ms) =>
    ms.forEach((m) =>
      m.addedNodes.forEach((n) => {
        if (
          n.nodeType === 1 &&
          (n.matches?.('[data-testid="thumb-reveal-skeleton"]') ||
            n.querySelector?.('[data-testid="thumb-reveal-skeleton"]'))
        )
          skel++
      })
    )
  ).observe(scroller, { childList: true, subtree: true })
  let minCards = 1e9
  const tick = (t) => {
    if (!run) return
    deltas.push(t - last)
    last = t
    minCards = Math.min(minCards, scroller.querySelectorAll('.media-card').length)
    requestAnimationFrame(tick)
  }
  requestAnimationFrame(tick)
  for (let i = 0; i < 30; i++) {
    scroller.scrollBy(0, 600)
    await new Promise((r) => setTimeout(r, 100))
  }
  for (let i = 0; i < 30; i++) {
    scroller.scrollBy(0, -600)
    await new Promise((r) => setTimeout(r, 100))
  }
  run = false
  const s = deltas.slice(1).sort((a, b) => a - b)
  console.log(
    JSON.stringify({
      frames: s.length,
      p95: s[Math.floor(s.length * 0.95)],
      max: s[s.length - 1],
      over50: s.filter((x) => x > 50).length,
      over100: s.filter((x) => x > 100).length,
      longtasks: longtasks.length,
      longtaskMax: Math.max(0, ...longtasks),
      skelAdds: skel,
      minVisibleCards: minCards
    })
  )
})()
```

**判定阈值**：B 相对 A 的 >100ms 帧数下降 ≥50% 且主观闪屏归零 → R1 确证；若 minVisibleCards 在滚动中骤降至 ~0 而帧间隔正常 → R5（虚拟化空窗）升级为主嫌，**回传读数后再议代码改动，不得先动 VIEWPORT_INCREASE**；若 B 无改善 → R1 否决，如实记录，补采 chromium-debug.log 再分析。
**D4 硬件重试试验（R2 的根因出口）**：安装修复版后，设置→通用→GPU 硬件加速→开→立即重启（pref=true 三轴齐清，获得干净硬件尝试）。预期 diag：`hwAccel=on(default)`、activeGPU=RTX 4060。观察数日：若 GPU 崩溃复发，阶梯自动回退且 glass-lite 自动保护（不再裸奔）；回传 gpu-fallback.json 与 diag.log。**此步有崩溃复发风险，须在修复版上进行，用户知情执行。**
**D5 睡眠验证（N3）**：扫描进行中合盖 30s 唤醒 → 预期 main.log 无 heartbeatTimeout、扫描继续。
