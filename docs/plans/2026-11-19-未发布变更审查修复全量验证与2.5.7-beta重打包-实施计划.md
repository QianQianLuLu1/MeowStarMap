## 一、审查结论（第 2 步的产出）

### 1.1 三个实质缺陷（修复已在工作区，需复核 + 全绿验证）

| 编号   | 缺陷                                                               | 根因                                                                                                                                                                                                                                                | 修复落点                                                                                                                                                                           |
| ------ | ------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **G1** | 图库板块只显示 500 张，左下角计数却是真值（如 1200）               | `useFilteredMediaFiles` 的 effect 只调一次 `loadNextMediaPage()`；被 `loadingMore`/`depthFetchActive` 挡下、取数失败、或被整刷顶掉（`mediaCursorWriteSeq` 变化）时它**静默返回且不写 state** ⇒ effect 三个依赖全不变 ⇒ 永不重跑 ⇒ 永久停在第 500 张 | `mediaStore.ts` 新增 `fillRemainingMediaPages()`（退避阶梯 + 有界放弃）+ `mediaRefreshEpoch`；hook 改调该函数并纳入依赖；`GalleryPage.tsx` 两处整刷补 `limit=max(500, 已加载条数)` |
| **G2** | 目录提案过期的短码到不了渲染层（`selection_expired` 分支永不命中） | contextBridge 复制 Error 时丢弃自定义字段 `details`                                                                                                                                                                                                 | `preload/api/nikkisync.ts`：命中 `upstreamCode==='selection_expired'` 时 `reject` 普通可克隆对象 `{code,message,details}`；`docs/IPC_CONTRACT.md` 同步                             |
| **G3** | JPEG 导出在客户端提前断开后，后续导出可能卡住                      | 异步 `getAssetDetail` 期间连接已 destroy，仍继续写响应                                                                                                                                                                                              | `sync/server/api-router.ts` 两处 `if (res.destroyed) return`（写头前 / 异步读取后）                                                                                                |

附带两处**用户可见**小修（同批改动）：`SyncServicePage.handleAddDirectory` 补 `setBusy(true)/finally`（系统选择器等待期可重复打开）；`e2e/nikkisync-runtime.e2e.ts` 改用 `parsePairingUri` 逐字段校验（多网卡 `nikki-sync://pair` 形态下原 `NS1|...` 7 段断言必红）。

### 1.2 观察项（**本轮不改**，写明理由）

- **O1** `fillRemainingMediaPages` 末尾 `if (pages >= MAX_DEPTH_PAGES) console.warn(...)`：若循环恰好在第 200 页自然收敛（`hasMoreMedia` 变 false），会误报「hit page cap」。触发条件是 200 页整，实际不可达（每次泵最多 5 次空闲尝试，需 40 轮才有机会叠加），且仅影响一条 warn 日志。按「最小化改动」不动代码，报告中登记为 P3 观察项。
- **O2** nikkisync 数据源下泵会连续拉全库（`loadNextAssetPage` 置 `hasMoreMedia=Boolean(nextCursor)`）。改前是「每页追加 → `mediaCount` 变 → effect 再触发」的等价级联，**非回归**；泵只是把级联改成顺序循环，仍是串行 await，无并发风暴。
- **O3** preload 只对 `selection_expired` 做结构化降级，其余 `IpcError` 跨桥仍丢 `details`。与 `docs/IPC_CONTRACT.md` 现口径一致（渲染层只有该码依赖 `details`），扩面属未发生需求。
- **O4** `CHANGELOG.md` 现有新增条目只是一行白话（未按仓库风格给出加粗标题/日期/影响面）。**本轮修**（见 T6），因为它同时是 `dist:win → pre-dist-check → check-changelog-release` 的入节凭据。

## 四、错误处理（既有实现，本轮只复核）

| 异常分支                                      | 处理                                                                                                                        | 兜底                                                         |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------ |
| `window.electronAPI.media.list` 缺失          | `loadMoreMedia` 返回 null → 泵判无进展 → 退避重试 → 阶梯耗尽 `console.warn('[mediaStore] auto-fill stalled', {...})` 后退出 | 保留已加载条数，`hasMoreMedia` 仍 true，计数继续取服务端真值 |
| IPC 抛 `IpcError`                             | `loadMoreMedia` catch + `console.error`，返回 null                                                                          | 不向 UI 抛错、不弹 toast                                     |
| 响应畸形（无 `files`）                        | 返回 null                                                                                                                   | 同上                                                         |
| `nextCursor` 不推进 / 谎报 hasMore            | 去重后长度不变 ⇒ 计一次无进展                                                                                               | 阶梯耗尽退出，不死循环                                       |
| 整刷顶掉（`depthFetchActive` / 游标代次变化） | 泵计一次无进展；整刷 `finally` 递增 `mediaRefreshEpoch`                                                                     | effect 依赖变化 ⇒ 拉齐链重启                                 |
| 泵自身抛错                                    | `try/finally` 复位单飞标志，异常内部消化                                                                                    | 不因一次异常永久卡死                                         |
| 组件卸载                                      | 泵是全局数据任务、不随卸载取消；阶梯有限（约 2.25s）                                                                        | 无长期定时器泄漏                                             |
| 提案过期（G2）                                | preload reject 可克隆对象                                                                                                   | 渲染层 `selection_expired` 收起预览并提示重选                |
| 客户端断连（G3）                              | 两处 `res.destroyed` 早退                                                                                                   | 请求结束、文件句柄已 `finally close`，后续导出不受影响       |

日志规则：只允许 `warn`/`error` 级别，英文串 + 结构化字段；不新增中文硬编码字符串（`src/**` 中文护栏为 error）。

## 五、参数校验

| --------------------------------- | ------------------------ | -------------------------- | ------------------------------------------------------------------------------ |

## 十一、风险与回滚

| 风险                                         | 缓解                                                                                                                                        |
| -------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------- |
| 泵与整刷互相拉扯                             | 单飞标志 + `loadingMore`/`depthFetchActive` 闸 + 去重追加 + 退避阶梯；整刷 `finally` 只发信号不改列表                                       |
| `mediaRefreshEpoch` 每次整刷 +1 造成额外渲染 | 仅 `useFilteredMediaFiles` 订阅；`useMemo` 命中缓存，列表引用不变则不重算                                                                   |
| 删除旧测试被误读为弱化                       | E2 保留「不得无限重试」语义（≤7 次尝试 + 放弃后不再自试）；报告注明新旧判据对照                                                             |
| e2e:smoke 打到旧产物                         | 冒烟前强制 `dist:win`；报告记录 `win-unpacked` 时间戳与提交时间先后                                                                         |
| 打包链某步失败（stage / pre-dist-check）     | 逐步定位：`stage:nikkisync-pc` → `pre-dist-check`（含 `check-doc-versions`、`check-changelog-release`）→ `electron-builder` → `verify:dist` |
| 回滚                                         | 三处修复彼此独立：`git revert <sha>` 或 `git checkout -- <file>`；无数据库迁移、无配置迁移、无依赖变更                                      |
