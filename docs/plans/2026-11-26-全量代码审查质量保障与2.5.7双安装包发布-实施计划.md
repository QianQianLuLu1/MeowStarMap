# MeowStarMap 全量代码审查、质量保障与 2.5.7 双安装包发布计划

## Context

用户要求对 `MeowStarMap2.5.7-Beta` 至当前 `main` 的 41 笔未发布提交及工作区改动做全面审查，优先修复逻辑、运行时、并发、内存资源、架构规范和 IPC/安全边界问题；随后用严格 TDD 完成回归，按指定顺序通过六项验证，创建 Conventional Commit，将所有负责版本字段精确同步为 `2.5.7`，并基于同一份最终 `win-unpacked` 同时生成 NSIS 与 Tauri 自研安装器。预期结果是：确认缺陷全部修复、测试先红后绿、六项验证和附加质量门禁全部退出码 0、两个职责清晰的本地提交、版本与发布元数据一致、最终工作区干净；不执行 push 或其他远端操作。

## 执行约束

- 仅修改审查范围内或验证失败直接相关的文件，不做无关重构、格式化、依赖升级或功能扩展。
- 每个确认缺陷执行“回归测试先失败 → 最小生产修复 → 同一测试转绿 → 相关子集回归”；不得跳过、删除、注释或弱化测试。
- 优先复用仓库现有框架、fixture、mock、原子文件工具和发布脚本；仅在系统边界 mock 外部依赖。
- 六项指定命令必须真实执行并依次以退出码 0 通过；任何失败均定位并修复，不以环境原因为由跳过。
- 版本更新与修复提交分开：第一笔提交承载审查修复、测试、CI/发布逻辑和计划文档；第二笔提交承载 `2.5.7` 版本字段与发布收口。
- 不 push、不创建 PR/MR、不发布远端 Release，不提交密钥、凭证或生成产物。

- 所有命令在仓库根目录执行；安装器前端命令使用 `npm --prefix installer ...`，Rust 命令使用 `cargo test/fmt/clippy --manifest-path installer/src-tauri/Cargo.toml`。
- 开发/功能验证：`npm run dev`；构建：`npm run build`；NSIS 候选包：`npm run dist:win`；Tauri 安装器：`npm run build:installer`。
- 每个缺陷使用现有 Vitest、Playwright 或 Rust `#[cfg(test)]` 用例记录红灯；修复后重跑同一用例，再运行相关目录/模块子集。

- 最终打包后再次运行产物冒烟和性能基线，确认安装包来自最终提交状态。

## 错误处理

- 主进程业务错误沿用 `AppError` 家族与 `wrapHandler`/`wrapHandlerNoArgs`，保留 `cause`，不向渲染层暴露完整路径、堆栈或密钥。
- 文件、worker、定时器、订阅、数据库连接、临时目录、锁文件和备份目录必须在成功与失败路径都清理；worker 释放先于数据库关闭。
- Rust 安装/卸载/更新链路使用 `Result` 传播错误，不把注册表、停止进程、重命名、回滚等失败降级为警告后继续。
- 外部参考数据、图片与诊断日志沿用既有 fail-soft/fail-open；路径授权、payload 校验、安装目标所有权与更新来源保持 fail-closed。
- 验证失败保留退出码和原始日志，先区分产品缺陷、测试缺陷或脚本/环境缺陷，再写能复现根因的回归；禁止重试、跳过、放宽断言或删除用例来制造绿色。

## 参数校验

- IPC 继续使用现有 zod schema 与 `wrapHandler`；路径复用 `assertFileReadPath` / `assertFileWritePath` / `assertMediaReadPath`，不复制校验逻辑。
- 安装目标只接受绝对路径，并按白名单识别：空目录、manifest 匹配且含预期 exe 的应用目录、或注册表记录且含预期 exe 的旧安装目录；其他已存在非空目录拒绝。
- payload 清单保持可选：缺清单时保留跳过 SHA256 的既有行为，但文件长度、footer 偏移、版本、格式、manifest 长度和算术运算必须校验，使用 checked 运算并设置明确上限。
- 正式更新只接受 electron-updater 返回或 `update-downloaded` 事件提供的可信路径，在主进程二次校验后保存于内存；渲染层不传安装器路径。
- 取消在解包/校验阶段有效并清理 staging；首次重命名旧目录后进入不可逆提交点，取消按钮禁用并显示明确提示。
- 卸载注册表写入失败视为安装失败，不允许出现“文件已安装但无法卸载”的成功假象。

## 基础测试用例

- 正常路径：公开服务/IPC 返回约定结果；安装、升级、卸载、更新下载与启动成功；版本、asar、payload 和发布 feed 一致。
- 异常路径：非法参数、路径拒绝、非白名单目录、payload 截断/溢出/版本不符、PowerShell 特殊字符、注册表失败、进程停止失败、文件替换失败均返回错误并释放资源。
- 边界条件：空集合、空目录、超大长度、零/负数、超限 manifest、并发安装、stale lock、延迟 Promise、WAL/SHM 文件、取消时点、同版本更新不生效。
- 每个新增 Bug 回归用例必须在修复前真实失败；若原本通过，重写至能暴露目标缺陷后再修复。
- 不改变现有覆盖率阈值，不扩大 coverage exclude，不把模拟宿主读数当作真实 CI 读数。

## 已确认的测试接缝

1. 公开函数/服务单测：正常、异常、边界输入。
2. IPC/preload 契约：通道、参数校验、错误映射、可信更新路径与资源清理。
3. Playwright 用户路径：关键用户流程、打包产物启动与更新/安装边界。
4. 版本/打包契约：版本号、安装包/asar、payload footer、SHA512 feed 与发布元数据一致性。

## 已确认的产品决策

- 安装目录采用安全白名单，不删除任意已存在目录。
- payload 清单保持可选，不引入强制清单策略。
- 正式更新切换到 Tauri：主进程使用 electron-updater 下载完成的可信路径，二次校验后启动自定义安装器；2.5.7 同版本客户端不会立即自动升级，链路从下一版本实际生效。
- CI 同步构建/发布 NSIS + Tauri 双包，正式 `latest.yml` 指向 Tauri 安装器。
- 取消语义：解包/校验可取消并清理 staging；首次重命名后禁用取消。
- 卸载注册表写入失败视为安装失败。
- 安装器子工程版本与主应用同步为 `2.5.7`。

## 审查方法

1. 执行前重新生成 `MeowStarMap2.5.7-Beta..HEAD` 的完整 hash 清单和 314 文件覆盖台账，逐笔标记“已读完整 diff / 已追踪调用链 / 已复核测试”。
2. 按提交簇分批阅读完整 diff，并追踪受影响调用链；不仅看变更行，还检查周边不变量、错误路径、资源生命周期、IPC 契约和跨平台路径语义。
3. 使用三个独立视角复核：①逻辑/运行时/并发与内存；②架构规范/IPC/安全边界；③测试/构建/发布与版本一致性。主 agent 负责去重、定级和最终结论。
4. 每个确认缺陷记录文件、触发条件、根因、可观察影响、红灯用例、最小修复、相关回归命令和最终状态；证据不足的怀疑只补 characterization，不直接改代码。
5. 41 笔提交和 314 文件覆盖完成前，不进入全量验证；覆盖台账保存在本地忽略目录，不提交生成台账。

## 验证与报告要求

### 六项指定验证（严格顺序）

1. `npm install`：退出码 0；比较安装前后 lockfile，无非预期依赖漂移；恢复并验证 NikkiSync junction。
2. `npm run build`：退出码 0；主进程、渲染层和预加载产物完整生成。
3. `npm run test`：退出码 0；包含安装器新增测试；记录通过、失败、跳过数量和总耗时，禁止新增静默 skip。
4. `npm run typecheck`：退出码 0；覆盖根应用、scripts、e2e 与安装器 TypeScript。
5. `npm run e2e:smoke`：退出码 0；在此之前执行候选 `npm run dist:win`，确认 Playwright 启动的是本次构建产物。
6. `npm run test:ci-linux`：退出码 0；确认从基座配置继承安装器测试，宿主模拟结果与真实 CI 面一致。

### 附加质量门禁

- 每个缺陷修复后：同一红灯用例转绿，再运行 `npm run verify` 与相关子集。
- 第一笔提交前：`npm run lint`、`npm run format:check`、`npm run i18n:guard`、`npm run typecheck:e2e`、`npm run test:coverage`、`npm run audit`、`npm run docs:links`。
- Rust：`cargo test --manifest-path installer/src-tauri/Cargo.toml`、`cargo fmt --manifest-path installer/src-tauri/Cargo.toml --check`、`cargo clippy --manifest-path installer/src-tauri/Cargo.toml -- -D warnings`。
- 版本提交后：版本/CHANGELOG/lock 契约测试、相关静态检查与 `npm run build`；任何源码变化补跑受影响测试和冒烟。
- 最终打包后：`npm run verify:dist`、`npm run e2e:smoke`、`npm run e2e:perf`、产物哈希/footer/feed/版本校验。
