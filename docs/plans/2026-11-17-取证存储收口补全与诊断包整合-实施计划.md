# 取证存储收口补全与诊断包整合 — 实施计划（2026-11-17）

> 本计划是同日《2026-11-17-取证存储统一到安装目录-实施计划.md》的补全轮：前轮建立了
> `forensics-dir.ts` 单一真相源，但启动时序、导出读取侧、硬编码写点仍有缺口，本轮逐一收口。

## 一、背景与问题

项目已有取证收口模块 `src/main/utils/forensics-dir.ts`（打包态 → `<exe 安装目录>\Diagnostics`，
不可写/dev → `Documents\喵星图\Diagnostics` → homedir → tmpdir 三级回退），但收口并未完全生效：

- **A 时序覆盖**：lifecycle 阶段2 `applyCustomDirectories` 先于阶段3 `initLogger`；
  `resolveCustomDir('logDir')` 默认 `userData\logs` → `setLogDirectory` 抢先，initLogger 幂等
  guard 跳过取证目录。主日志/故障日志常态落 `%APPDATA%\...\logs`。
- **B 崩溃目录分裂**：index.ts 早期 crashDumps=取证根；阶段2 custom-dirs 又重设为 Documents 链。
- **C 导出读写错位**：`log-service.ts` 从 Documents 读 chromium/diag 日志、从 userData 读 gpu
  文件，而写入端全在取证根 → 打包态导出诊断包系统性缺 5 类文件。
- **D 硬编码**：`cleanup.ts` 固定写 `userData\logs\faults-*.jsonl`。
- **E 游离**：`scan-log.jsonl` 落 userData 根，不进诊断包。
- **F 暂存漂移**：诊断打包 tmpDir 随 logDir 摆动。
- **G NikkiSync**：5 个聚合诊断文件落 `userData\nikkisync`（宿主注入，可改向，上游包零改动）。
- **H 历史残留**：旧位置文件需自动迁移。

**用户决策**：① 取消 logDir/crashDir 自定义入口，强制统一（历史值迁移后清键）；② 保留安装
目录不可写时的三级回退链；③ 归集范围含 NikkiSync 5 个诊断文件；④ 历史文件启动时自动迁移。

**目标终态**：所有取证文件统一落 `getForensicsRoot()`；右下角「导出诊断包」从同一根收集完整
数据（manifest 升 1.2）；安装目录文件作为窗口拉不起时的应急取证。双机制同源、互不冲突。

## 四、错误处理与参数校验（贯穿设计）

- 迁移/收集全链 fail-open：单文件失败不阻塞启动/导出；失败经 `logStartupError`/`logger.warn` 留痕。
- `migrateDirFiles` 新增可选参 `{ skipExisting?: boolean }`（默认 false 向后兼容）：dst 已存在
  则跳过保留 src——保护本次启动已写的新鲜证据（heartbeat/chromium 日志等）。
- `getForensicsFilePath(name)` 既有守卫（禁分隔符/..）继续生效；NikkiSync 迁移模式严格匹配
  5 个文件名，绝不匹配 nikkisync.db。
- IPC setDir/resetDir 通道保留、返回结构（DirOpResult）不变：setDir 返回 `success:false`+已统一
  说明；resetDir 返回 `success:true, needRestart:false`。
- 回退态（根==Documents）源=目标由 migrateDirFiles 既有同路径跳过自动处理；清键幂等 ⇒ 二次启动 moved=0。
