## 3. 深度审查结论与修复设计

> 严重度：P0 阻断 / P1 功能错误 / P2 明确缺陷 / P3 规范或体验。所有 P2 修复均先加红灯测试。

### F1（P2）最近删除入口图标被改成 `album`，与灵感库重复

- 证据：`SyncConsoleLayout.tsx:31-32` 现为 `organizer: 'album'` 与 `inspiration: 'album'`；而 `ConsoleIcons.tsx:4-5` 注释明确写着"另补 1 个 `trash` 供「最近删除」入口与灵感库区分"。改后 `trash` 图标在全仓无任何消费者。
- 影响：侧栏两个入口视觉无法区分，违背既有设计约定。
- 修复：`NAV_ICONS.organizer` 改回 `'trash'`。
- 红灯测试（`sync-console-design.test.ts`）：断言布局源码含 `organizer: 'trash'` 且不含 `organizer: 'album'`；修复前失败。

### F2（P2）删除 `SyncStatusBar.test.tsx` 后，重启/导出的异常路径覆盖未迁移

- 证据：旧测试覆盖"重启失败""桥面缺席""导出失败/取消/桥面缺席"；现 `ConnectView.test.tsx` 只覆盖导出成功，`SyncConsoleLayout.test.tsx` 只覆盖重启成功。
- 影响：迁移后的 `handleRestart` / `exportDiagnostics` 异常分支无回归锁，属测试覆盖回退。
- 修复：在 `ConnectView.test.tsx` 补 5 个特征化用例（不复制实现）：
  1. 重启失败 → `showError` 被调用（`restartServer` reject）。
  2. 重启桥面缺席（删除 `window.electronAPI.nikkisync.restartServer`）→ `showMessage(..., 'info')`，不抛 TypeError。
  3. 导出返回 `{ success: false }` → `showError`。
  4. 导出桥面缺席（删除 `window.electronAPI.log.exportZip`）→ `showMessage(..., 'info')`。
  5. 导出取消（抛 `code === ERROR_CODES.CANCELED`）→ 静默（`showMessage` 不被调用）。
- 输入/输出：渲染 `ConnectView`，点击 `sync-status-restart` / `sync-status-export`；输出为 Toast mock 调用序列。
- 验收：5 个用例通过；不改产品行为。

### F3（P2）`space-y-*` 迁移到无样式的 `sc-service-rows`，列表分隔线与嵌套间距丢失

- 证据：
  - 全仓 CSS 无 `.sc-service-rows` 定义（仅 JSX/e2e/文档引用），它是纯语义类。
  - `sc-card-body` 的 `gap: 14px` 只作用于**直接子级**；嵌套在 `sc-service-rows` 里的元素拿不到。
  - 逐项包裹破坏 `.sc-setting-row:first-child { padding-top:0; border-top:0 }`：账户列表、额外目录、关于页仓库/反馈的每一行都成了自己容器里的 `:first-child`，分隔线与上内边距全部消失。
  - 非行内容（照片目录输入框+按钮、热点/网络说明+按钮、额外目录标题+列表）由 `space-y-2`（8px）改为无样式类后间距归零。
- 影响：Settings / About / 网络与热点卡的纵向节奏与分隔线退化，属本次改动引入的可见 UI 回归。
- 修复（最小、可复用现有 CSS 机制）：
  1. `sync-console.css` 新增局部类（沿用设计系统作用域）：
     ```css
     .sync-console .sc-stack {
       display: flex;
       flex-direction: column;
       gap: 8px;
       min-width: 0;
     }
     ```
  2. `SettingsView.tsx`
     - 照片目录输入组（约 L985）：`sc-service-rows` → `sc-stack`。
     - 额外目录外层（约 L1031，带 `data-testid`）：`sc-service-rows` → `sc-stack`（标题块与列表之间 8px）。
     - 账户列表（约 L874）：去掉逐项 `<div className="sc-service-rows" key=...>`，直接渲染 `<ConsoleRow key=...>`，恢复行间分隔线。
     - 额外目录列表（约 L1046）：同上去掉逐项包裹。
  3. `HotspotCard.tsx`（约 L109）、`NetworkPermissionCard.tsx`（约 L114、L146）：`sc-service-rows` → `sc-stack`（保留 `pt-1` 等修饰）。
  4. `AboutView.tsx`
     - 反馈区（约 L153-179）：保留一层 `sc-service-rows`，去掉两个单行内层包裹，让两行成为兄弟节点，恢复分隔线。
     - 仓库区（约 L184-203）：去掉逐项包裹，五行为兄弟节点。
- 红灯测试（`sync-console-design.test.ts`）：
  - 断言 `SettingsView.tsx` / `AboutView.tsx` 不再出现 `<div className="sc-service-rows" key=`。
  - 断言 `sync-console.css` 含 `.sync-console .sc-stack`，且 `SettingsView.tsx`、`HotspotCard.tsx`、`NetworkPermissionCard.tsx` 均使用 `className="sc-stack"`。
- 验收：两个新测试由红转绿；`sc-service-rows` 继续作为行列表语义容器，行间距/分隔线由 `.sc-setting-row` 自身承担。

### F4（P3）`ConsoleSection` 在渲染期执行 `console.error`

- 证据：`console-ui.tsx` 的 `ConsoleSection` 新增 `if (!title) console.error(...)`；`title` 是必填 `string`，TypeScript 调用方不会传空值，该分支不可达且属渲染期副作用（StrictMode 双渲染、测试噪声）。
- 修复：删除该分支，保留必填类型约束。
- 验收：无行为变化，全量测试无新增 console 输出断言失败。

### F5（P3）陈旧注释与文档漂移

- `SyncConsoleLayout.tsx:48-52` 仍写"h2 / 全宽底栏 / 页面级 h3"，实际已是 h1 且无底栏。
- `SyncServicePage.test.tsx:6` 注释仍提 `SyncStatusBar`。
- `ConnectView.tsx:94` T3 清单未列"重启服务"。
- 修复：仅改注释，不改代码逻辑。

### F6（决策项，不改代码）恢复提示与旧 i18n 键

- 旧底栏的 `syncConsole.statusBar.recoveryHint`（"服务恢复入口始终在此，无需切换页面"）随底栏删除而失去渲染点；该文案在无底栏的新 IA 下已不成立。
- 决策：**保留删除**（与上游 DesktopPage 形态一致），不恢复底栏；12 语包键按 i18n 守卫约定保留（键集测试仍要求存在），作为历史键不删。`statusBar.version/aligned`、`about.version.title` 同理。
- 验收：i18n 键集/非空守卫通过，无新增硬编码文案。

### F7（观察项，不改）`AboutView` 冗余嵌套与品牌图无 onError

- `AboutView` 反馈/仓库保留一层无样式包裹，属语义分组，无行为影响；品牌图是随包资源，缺图风险由构建期资源校验覆盖。纳入观察，不在本轮扩大改动。
