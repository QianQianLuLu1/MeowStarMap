# 计划：QMind Knowledge 插件同名碰撞归属记录

> 日期：2026-10-04
> 来源：/better-harness 资产完整性检查发现 `qmind-knowledge-cn` 与 `qmind-knowledge-cn-vpc` 的 `displayName` 均为 "QMind Knowledge" 形成同名碰撞组
> 性质：只读判定 + 项目侧记录，不改动 Plugin 启用/停用/卸载状态

---

## 1. 依赖声明

- 无新增/变更依赖
- 无外部工具安装需求
- 仅涉及现有文档追加一段已知状态登记

## 2. 启动说明

- 环境准备：无需编译或运行任何代码
- 操作对象：`docs/技术债清单.md`（追加 §11）
- 验证方式：
  1. 确认记录内容正确描述两个包的适用边界与当前所有者
  2. 执行 `<cli> coding-agent-practices asset-integrity` 重跑资产完整性检查，确认碰撞组被文档解释
  3. grep 确认项目 Rules/Skills/MCP 配置中无 qmind 引用产生矛盾的所有者声明

## 3. 错误处理

- 异常分支：若资产完整性检查工具不可用 → 记录为"检查待补"，不阻断本次记录写入
- 兜底策略：如发现项目内有其他文档提及 qmind 且声明了不同所有者 → 停止并报告矛盾
- 日志输出：本计划文件本身为执行记录

## 4. 参数校验

- 输入：Plugin cache 中两个 plugin.json + SKILL.md 的实测内容
- 必填项：碰撞原因（displayName 相同）、判定结论、适用边界
- 边界：仅记录事实，不执行 Plugin 变更操作
- 非法值：若 plugin.json 格式异常或 displayName 实际不同 → 重新分析

## 5. 基础测试用例

| 类型 | 用例                                                               | 验收标准                   |
| ---- | ------------------------------------------------------------------ | -------------------------- |
| 正常 | 记录写入后 grep 技术债清单包含 "qmind-knowledge"                   | 命中 ≥ 1 行                |
| 正常 | 记录明确写出两个包各自的适用环境与当前所有者                       | 人工审阅通过               |
| 异常 | 若 `docs/技术债清单.md` 不存在                                     | 停止并报错，不新建平行文档 |
| 边界 | 检查 `.qoder/rules/` 与 `.qoder/skills/` 中无 qmind 相关所有者声明 | grep 返回 0 匹配           |

## 6. 子任务分解

### 任务 A：写入归属记录

- **修改文件**：`docs/技术债清单.md`（追加 §11）
- **输入**：本次分析结论（见上表）
- **输出**：§11 段落，包含：碰撞原因、两个包适用边界、当前所有者判定、对本项目影响
- **验收标准**：
  - `grep -c "qmind" docs/技术债清单.md` 返回 > 0
  - 段落格式与既有 §6-§10 一致
  - 不创建新文件

### 任务 B：验证无矛盾

- **修改文件**：无（只读检查）
- **输入**：项目内 `.qoder/rules/`、`.qoder/skills/`、`mcps/` 配置
- **输出**：确认无 qmind 相关引用（已预验通过）
- **验收标准**：grep 全部返回 0 匹配

### 任务 C：重跑资产完整性检查

- **修改文件**：无
- **输入**：better-harness CLI
- **输出**：确认同名碰撞组存在且已有项目侧文档解释
- **验收标准**：检查正常返回，碰撞组仍列出但文档已记录
