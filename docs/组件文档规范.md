# 组件文档规范

> 适用范围：`src/renderer/` 下全部渲染层组件。
> 配套工具：Storybook（启动与排错见 `docs/Storybook使用指南.md`）。
> 样板参照：`src/renderer/components/common/Spinner.stories.tsx`（阶段 1 冒烟样例，所有新 story 严格沿用其风格与约定）。

## 1. 总则

组件文档不依赖单独维护的 Markdown，而是由「源码注释 + stories + 自动化文档页」三者共同构成：
组件源码负责"是什么"（JSDoc），stories 负责"怎么用、有哪些状态"，Storybook autodocs 负责"汇总呈现"。
任何一处缺失都视为文档不完整。

## 2. 七要素要求

每个组件的文档必须覆盖以下七个要素：

| #   | 要素            | 落地方式                                                                                                                                                                     |
| --- | --------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ①   | 组件说明        | 组件文件顶部（`export const` 之前）写 JSDoc 块，说明用途、设计目标与使用示例；react-docgen 自动提取为 Docs 页的组件描述。组件顶部缺 JSDoc 会导致 Docs 页无描述，视为文档缺陷 |
| ②   | Props / API     | Props 接口逐字段写 JSDoc（`/** ... */`），autodocs 自动生成 argTypes 表格（含类型、默认值、描述）。禁止"裸接口"——字段无注释等于文档缺失                                      |
| ③   | 使用示例        | Docs 面板自动展示每个 story 的源码；组合用法（多组件协作、真实业务上下文）写入 `docs/storybook/**/*.mdx`（MDX 入口已在 `.storybook/main.ts` 的 stories glob 中）             |
| ④   | 交互状态        | `loading` / `empty` / `error` / `disabled` 等关键状态各自独立成 story，命名直白（如 `Loading`、`Error`、`Disabled`），不允许只给一个 Default 蒙混过关                        |
| ⑤   | 主题样式        | 全局 `theme` arg 由 `.storybook/decorators/theme.tsx` 统一切换（经 `themeStore.applyTheme`），story 内不得写死与主题冲突的颜色；色板总览页后续补充                           |
| ⑥   | 无障碍          | 已接入 `@storybook/addon-a11y`，组件需经得起其扫描；在 `parameters.docs.description` 中注明该组件的角色（role）/ 键盘操作 / 对比度要点                                       |
| ⑦   | 测试 / 预览入口 | story 的 `parameters.docs.description.component` 或同目录 MDX 中注明同置测试文件 `*.test.tsx` 与运行命令 `npm run test:renderer -- <相对路径>`                               |

## 3. 命名与组织约定

- **同置**：`Component.stories.tsx` 与组件源码放在同一目录（`src/renderer/components/<域>/`）。
- **title 按目录分层**：
  - `src/renderer/components/common/` → `Common/xxx`
  - `src/renderer/components/gallery/` → `Gallery/xxx`
  - `src/renderer/components/editor/` → `Editor/xxx`
  - `src/renderer/components/layout/` → `Layout/xxx`
  - 其余目录就近归入上述四类，或与目录名一致。
- **autodocs**：meta 必须带 `tags: ['autodocs']`（`.storybook/main.ts` 采用 `'tag'` 策略，不带标签不生成文档页）。
- **story 命名**：`Default / <状态> / <变体>`，如 `Default`、`Disabled`、`Error`、`Large`、`WithAction`。
- **meta 与 story 注释**：中文，简洁，说明"这个变体在演示什么"。

## 4. 依赖 `window.electronAPI` 的组件

- `.storybook/mocks/electron-api.ts` 已在 `preview.ts` 全局挂载双层 Proxy 安全桩：任意命名空间下的方法调用默认 `console.debug` 提示并 `resolve(undefined)`，保证故事可渲染、不抛错。
- 需要具体返回值才能展示有意义状态时，在 story 内覆盖，并在 story 注释或 `parameters.docs.description` 中**注明用到的命名空间与方法**（如 `log.exportZip`、`app.onUpdate`）。
- 覆盖必须通过 meta/story 的 `beforeEach` 注解**整体替换 `window.electronAPI`**，并在返回的清理函数中还原回原对象，避免污染其他故事。注意：全局桩是双层 Proxy（无 `set` trap，每次读属性都返回新子 Proxy），直接对桩写属性（如 `window.electronAPI!.app = {...}`）会被静默丢弃而**不生效**。可参考 `UpdateDialog.stories.tsx` / `FeedbackDialog.stories.tsx` 的 `mockAppNamespace` / `mockLogNamespace` 写法。
- 组件源码一律以可选链 `window.electronAPI?.xxx.yyy()` 访问 IPC；story 不得假设真实主进程存在。

## 5. i18n 文案约定

- 故事文案优先复用组件既有 i18n key（组件内部走 `t()`），不新造孤立 key。
- eslint 已对 `src/**/*.stories.tsx` 豁免 i18n 硬阻断，但豁免只是工具兜底：**示例数据中的字符串**（如 toast 消息、对话框标题演示值）允许直写，**组件渲染路径上的文案**必须来自 `t()` 或组件自身 props。
- 语言切换验证：工具栏 `语言` 下拉覆盖 12 个语言（默认 `zh-CN`），切换后 story 应即时重渲染。

## 6. 增量规则（强制）

- 新增组件：必须随组件同提交附带 `*.stories.tsx`（至少 `Default` + 全部关键状态）。
- 重大修改组件（Props 变更、新增状态、视觉重做）：必须同步更新对应 story，保证 Docs 页与实际行为一致。
- 组件顶部缺 JSDoc 属历史欠账：发现后登记到 `docs/技术债清单.md`，不强制顺手补改源码。

## 7. 最小 story 骨架

```tsx
import type { Meta, StoryObj } from '@storybook/react-vite'
import { MyComponent } from './MyComponent'

/** 一句话说明该组 story 覆盖哪些状态/变体 */
const meta: Meta<typeof MyComponent> = {
  title: 'Common/MyComponent',
  component: MyComponent,
  tags: ['autodocs'],
  parameters: {
    docs: {
      description: {
        component:
          '组件定位与设计目标。无障碍要点：角色 / 键盘 / 对比度。同置测试：`MyComponent.test.tsx`（`npm run test:renderer -- src/renderer/components/common/MyComponent.test.tsx`）。'
      }
    }
  }
}

export default meta
type Story = StoryObj<typeof MyComponent>

/** 默认状态 */
export const Default: Story = {}

/** 关键状态：例如禁用态 */
export const Disabled: Story = {
  args: { disabled: true }
}
```
