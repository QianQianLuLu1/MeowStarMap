# 修复计划：全屏图片浏览退出按钮与窗口控制按钮（WCO）重叠

## 1. 问题定位与根因分析

### 1.1 现象

图片放大预览（全屏浏览）打开后，窗口右上角同时出现两个"关闭按钮"互相重叠：

- **软件退出按钮**：窗口原生控制按钮（最小化/最大化/关闭）中的关闭按钮；
- **图片浏览退出按钮**：全屏浏览顶栏右侧的 ✕（IconClose）按钮。

### 1.2 根因（已通过源码确认）

| 因素                                 | 证据                                                                                                                                                                              | 结论                                                                                                 |
| ------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------- |
| 窗口无边框 + Window Controls Overlay | `src/main/app/window-manager.ts` L52-57：`titleBarStyle: 'hidden'` + `titleBarOverlay: { color: 'rgba(0,0,0,0)', symbolColor: '#1A1A1A', height: 40 }`                            | 窗口右上角悬浮**原生**窗口控制按钮（约 40px 高、138px 宽），位于网页内容之上的原生层，无法被内容遮挡 |
| 全屏查看器是"伪全屏"                 | `src/renderer/components/gallery/FullscreenViewer.tsx` L287：`fixed inset-0 z-[80]`；`uiStore.ts` 的 `openFullscreen` 仅置 store 状态，**未调用** `requestFullscreen()`           | 原生窗口控制按钮在伪全屏下依然显示                                                                   |
| 顶栏按钮定位                         | `FullscreenViewer.tsx` L326：顶部工具栏 `absolute top-0 left-0 right-0 h-14 px-4`，右侧按钮组 `flex items-center gap-2` 右对齐，最右端即"图片浏览退出按钮"（IconClose，L451-458） | 该按钮位于窗口最右上角 (16px, 0~~40px) 区域，与 WCO 关闭按钮区域 **0~~138px × 0~40px 完全重叠**      |
| 同类组件                             | `SlideshowPlayer.tsx` L245：`fixed inset-0 z-[85]`；L279 顶部信息栏 `absolute top-0 h-12 px-4`，右端退出按钮（L297-304）                                                          | 幻灯片播放器存在**同一根因**的重叠                                                                   |

### 1.3 修复策略

利用 Window Controls Overlay 官方提供的 CSS 环境变量 `env(titlebar-area-width)`（= 标题栏可用区宽度 = 窗口宽度 − 控制按钮区宽度）给右上角按钮组施加动态右侧避让边距，使"图片浏览退出按钮"整体左移出 WCO 按钮区。

- 避让量 = `calc(100vw - env(titlebar-area-width, 100vw))`；
- 非 WCO 环境（浏览器预览等）下 `env()` 取 fallback `100vw`，避让量自动归零，不影响常规布局；
- 纯 CSS 表达式，**零新增依赖、零 JS 逻辑、零状态管理改动**，满足最小化修改原则。

## 4. 错误处理（边界情况与容错机制）

| 边界情况                                                             | 容错机制                                                                                                      |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------- |
| 非 WCO 环境（`npm run build:preview` 浏览器预览、无 overlay 的窗口） | `env(titlebar-area-width, 100vw)` 取 fallback，避让量 = 0，布局与修复前完全一致，无回归                       |
| 不同屏幕分辨率 / Windows 缩放（100%/125%/150%）                      | `env()` 由 Chromium 按窗口实际布局实时计算，任何分辨率与 DPI 缩放下避让量始终精确等于按钮区宽度，无需手动适配 |
| 不同 Windows 版本按钮区宽度差异（Win10/Win11）                       | 不使用硬编码像素值（如 138px），避让量完全跟随实际按钮区宽度                                                  |
| 窗口尺寸过小（minWidth 900）导致标题挤压                             | 避让只作用于按钮组右外边距，标题区 `truncate max-w-[50%]` 与 Flex 收缩机制不受影响；验证用例覆盖最小窗口宽度  |
| 深色/浅色主题下按钮可见性                                            | 修复仅调整布局边距，不改变任何颜色与透明度样式                                                                |
| 控制按钮区未来位置变化（`titlebar-area-x` 非零）                     | 避让表达式同时扣除 `env(titlebar-area-x, 0px)`，即使按钮区不贴右边缘也精确避让                                |

## 5. 参数校验

本修复为纯 CSS 布局调整，不涉及 JS 函数入参、配置项或动态数据，但需校验：

| 校验项                        | 规则                                                                                               | 失败处理                                                                                                                                              |
| ----------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| CSS 表达式合法性              | `calc(100vw - env(titlebar-area-width, 100vw) - env(titlebar-area-x, 0px))` 必须能被 Chromium 解析 | `npm run typecheck` 后启动 `npm run dev`，若 DevTools 出现无效属性警告，立即回退为简化表达式 `calc(100vw - env(titlebar-area-width, 100vw))` 重新验证 |
| env() fallback 语义           | 非 WCO 环境必须解析为 0 避让（不破坏常规布局）                                                     | 在 `npm run build:preview` 预览模式下检查右上角按钮间距与修复前一致                                                                                   |
| 内联 style 与 Tailwind 类冲突 | `gap-2`/`px-4` 等类不覆盖 `marginRight`（Tailwind 的 `mr-*` 未使用，无优先级冲突）                 | 视觉验证按钮组仍保持 8px 间距、16px 右内边距语义                                                                                                      |

- ❌ 不修改主进程窗口配置（不动 `titleBarStyle`/`titleBarOverlay`）；

- ❌ 不引入新的 npm 依赖、不新增工具函数文件；
- ❌ 不做任何与本次重叠无关的重构或样式调整（如 EXIF 浮层 `top-16 right-4` 经核实 64px > 40px 无冲突，保持不动）；
- ❌ 不使用硬编码像素值（如 138px）作为避让量。
