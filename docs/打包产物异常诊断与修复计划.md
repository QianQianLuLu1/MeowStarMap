## 0. 结论速览

打包后"产物不可用 / 前端页面异常"的根因是**根目录缺失关键构建配置与 lockfile**（这些文件此前被移入 `Za/` 镜像子目录，根目录已不再保留），导致：

- **样式管线断裂（P0）**：Vite 从项目根自动发现 PostCSS/Tailwind 配置，根目录缺失 `postcss.config.cjs` 与 `tailwind.config.ts` 时 Tailwind 不运行，`globals.css` 的 `@tailwind` 指令被原样保留成非法 CSS，所有 Tailwind 工具类不生成 → 整站无样式、布局崩坏（即"前端页面异常"的典型表现）。
- **依赖版本漂移（P0）**：根目录缺失 `package-lock.json`，`npm install` 按 semver 范围解析装出与项目不一致的依赖版本（与"本地版本与项目不一致"的提示吻合），进而构建产物不一致甚至不兼容。
- **preview 构建脚本失效（P1）**：`package.json#build:preview` 引用 `./vite.preview.config.ts`，该文件仅存于 `Za/`，根目录运行会报错。

`Za/` 经核查是配置镜像（副本），**根是真实工程**，修复方向是把缺失文件复制回根，而非切换到 `Za/`。

已完成的修复：已将 `postcss.config.cjs`、`tailwind.config.ts`、`vite.preview.config.ts`、`package-lock.json` 从 `Za/` 复制回项目根。

## 2. 可能原因分析

### 已证实问题（回归根因）

#### F1【P0】样式管线断裂 ← 最可能直接导致"前端页面异常"

- **证据**：根目录缺失 `postcss.config.cjs`、`tailwind.config.ts`（仅 `Za/` 有）；`src/renderer/styles/globals.css` 强依赖 `@tailwind` 指令；`dist/renderer/assets/index-KEbnbck0.css` 已被正确处理过（反证）。
- **机制**：Vite 从 cwd（项目根）自动发现 `postcss.config.*`/`tailwind.config.*`。缺失时 Tailwind 插件不运行，`@tailwind` 指令保留为非法 CSS，所有工具类（`flex`/`grid`/`fixed`/`bg-primary` 等）不生成 → 整站无样式、布局崩坏。
- **状态**：已通过复制配置文件修复，待构建验证。

#### F2【P0】依赖版本漂移

- **证据**：根目录缺失 `package-lock.json`（仅 `Za/` 有）；用户明确提示"本地版本与项目不一致"。
- **机制**：无 lockfile 时 `npm install` 按 semver 范围解析版本，不同机器/时间装出不同（甚至不兼容）版本（vite / electron-vite / electron / @vitejs/plugin-react 等 minor 漂移）→ 产物不一致、构建行为差异 → "产物不可用/前端异常"。
- **状态**：已复制 `package-lock.json` 回根，后续须改用 `npm ci` 固定版本。

#### F3【结构判定】`Za/` 是配置镜像而非项目根

- **证据**：`Za/` 含 `electron.vite.config.ts` 等副本（根比 `Za/` 多 `decryption-worker` 入口，根为最新）；根另有 `src/`、`scripts/`、`resources/`。
- **结论**：修复方向是**从 `Za/` 复制缺失文件回根**，而非切换工作目录到 `Za/`。

### 已验证"非根因"项

#### F4【路径映射·已验证正确】

`app://renderer/index.html` → `dist/renderer`，preload → `dist/main/main/preload.js` 均正确。注意 `dist/main/main/` 的"双 main"嵌套依赖 electron-vite 输出结构，较脆弱，列为构建后复查项（非当前异常根因）。

#### F5【Worker 入口名一致性·已验证一致】

经 code-explorer 子代理深度核查，6 个 worker 的分叉点文件名与产物名**完全一一对应**，全部采用 `path.join(__dirname, '<name>.js')` 相对拼接，与 `dist/main/main/app/` 嵌套结构匹配：

| Worker 产物名          | 分叉代码位置                                                 | fork 文件名拼接                                |
| ---------------------- | ------------------------------------------------------------ | ---------------------------------------------- |
| `scanner-worker.js`    | `src/main/scanner/scanner-worker-bridge.ts:102`              | `path.join(__dirname, 'scanner-worker.js')`    |
| `media-worker.js`      | `src/main/media-worker/bridge.ts:98`                         | `path.join(__dirname, 'media-worker.js')`      |
| `thumbnail-worker.js`  | `src/main/thumbnail/worker-bridge.ts:98`                     | `path.join(__dirname, 'thumbnail-worker.js')`  |
| `video-worker.js`      | `src/main/video-editor/bridge.ts:106`                        | `path.join(__dirname, 'video-worker.js')`      |
| `database-worker.js`   | `src/main/database/worker/database-worker-bridge.ts:107,277` | `path.join(__dirname, 'database-worker.js')`   |
| `decryption-worker.js` | `src/main/decryption-worker/bridge.ts:101`                   | `path.join(__dirname, 'decryption-worker.js')` |

→ **文件名/路径无偏差，无需修复**。唯一可优化：`database-worker-bridge.ts:106` 注释声称 `__dirname` 在 `dist/main/main/database/worker/`，实际因 main.outDir=`dist/main/main/app` 而落在 `app/`（注释过时，不影响运行）。

#### F6【CSP 一致性·已验证】

`src/renderer/index.html` 的 meta CSP 与 `window-manager.ts` 的 `onHeadersReceived` CSP 逐字一致（`script-src 'self'`、`style-src 'self' 'unsafe-inline'`）。`stripCrossOriginOnTags` 插件、`type:module` 加载桩、class fields 降级、import.meta.url 取 preload basename 均为既有健壮性措施，恢复配置后须确认仍完好。

#### F7【build:preview 失效·已修复】

根 `package.json#build:preview` 引用 `./vite.preview.config.ts`，该文件此前仅存于 `Za/`，根目录运行报错。已将 `vite.preview.config.ts` 复制回根（P1）。

#### F8【渲染器别名安全·已验证安全】

渲染器源码中**不存在**静态 `import 'electron'` 或 `import '@main/...'`（0 命中）。唯一涉及 bare `electron` 的是 `electron.vite.config.ts:200` 的别名定义（指向 `scripts/electron-browser-stub.js`）。渲染器对 `electron` 的唯一真实引用是动态 `await import('pluggable-electron/renderer')`（`plugin-runtime.ts:106`，被 try/catch 包裹），且经别名 stub 重写，不会导致 sandbox 白屏。→ **无需修复**（建议加 lint 守门防回归）。

#### F9【环境变量·已验证正确】

- `__PREVIEW__`：定义于 `electron.vite.config.ts:205`（exe 版硬编码 `false`，走死代码消除）；业务仅 `src/renderer/utils/file.ts:18` 一处分支（预览版处理 `mock://`），exe 版被 tree-shake 消除，不影响产物。
- `NODE_ENV`：唯一判断点 `window-manager.ts:42`（`isDev = process.env.NODE_ENV === 'development'`）。其余 `process.env` 使用均为非 NODE_ENV 变量，与 dev/prod 分支无关。打包后 `NODE_ENV` 通常为 `production` → `isDev=false` → 正确走 `app://renderer/index.html` 分支。→ **无打包后误走 dev 分支风险，无需修复**。

### 补充检查点结论

- **路由**：依赖中无 `react-router`，`App.tsx` 用 `lazy()` + `Suspense` + `uiStore` 的 `ViewLevel`/`visitedViews` 做自研视图切换，不依赖 URL/history API → `app://` 下无路由失效白屏风险。
- **electron-builder**：配置在 `package.json#build`（无独立 `electron-builder.yml`）；`files` 覆盖 `dist/**/*` 与 `resources/**/*`；`asarUnpack` 含 `nuan5_decryption.dll`、`sharp/**`、`koffi/**` 等；`resources/nuan5_decryption.dll` 存在。脚本目录无 `afterPack.js`，无需额外处理。
- **dist/main/package.json 桩**：`{type:'commonjs'}` 由 build 脚本写入，避免 CJS 产物被当 ESM 解析。
