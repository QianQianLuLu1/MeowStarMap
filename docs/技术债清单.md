## 5. 处理建议

1. **优先清理分类 A 的渲染层提示**（imageProcessor / useImageProcessor / useIpcCall / WatermarkPanel / diagnostics-sections）：这些是用户可见文案，接入 `t()` 收益最直接。

3. **`game-events.ts` 数据重构**：涉及存储结构与 UI 两层，改动面较大，建议单独排期。
4. **分类 B（内部日志）**：维持现状，不强制翻译；若未来引入结构化日志语种统一，再一并处理。
5. **分类 C**：永不翻译，仅保留注释。

>
> 附注：`Gallery/VirtualImageGrid` 初次挂载时另观察到 Virtuoso 瞬时 `Maximum call stack size exceeded`
> （可自愈，不影响渲染），为第三方库行为，一并登记于此。

> 状态更新（2026-09-29）：已完成根因定位与修复，原计划文档 `docs/plans/2026-09-29-fix-gallery-stack-overflow.md` 已于 2026-10-01 归档至 `docs/archive/plans/`（被 `.gitignore` 排除，不入仓，git 历史可查）。
> 根因为 react-virtuoso 网格响应式图内部的「发布 → combineLatest 输入处理器 → 再发布」同步回路，
> 本项目侧有两个放大器：`components` 引用随响应式列数变化而变更导致列表子树重建（测量重新发布），
> 以及同一网格叠加 `overscan` 与 `increaseViewportBy` 两个视口放大旋钮。
> 修复：`VirtualImageGrid` 的 `components` 引用改为恒定（`columns` / `footerText` 经 ref 读取），
> 并移除 `overscan`，`GalleryPage` 的区域级 `ErrorBoundary` 继续保留作为第三方兜底。
>
> 缓解（2026-08-26）：`GalleryPage` 已将五个视图包入区域级 `ErrorBoundary`，`resetKeys`
> 由 `[viewMode]` 增强为 `[viewMode, filterSignature, retryNonce]`——`filterSignature` 由当前筛选/排序/搜索条件稳定派生，
> `retryNonce` 在 `ZoneErrorFallback` 的 `reset` 回调中 +1，使手动重试也改变 key、强制子树重新挂载，
> 即使栈溢出由某个稳定数据条件（而非视图本身）触发也能在用户主动重试时换 key 尝试恢复。
> `ErrorBoundary` 向 fallback 透传 `retryCount`/`maxRetries`（默认 3），达到上限后 `ZoneErrorFallback`
> 转为降级提示（`errorFallback.zoneDegraded`），避免「重试仍炸」的死循环体验；仍保留 `reset` 供用户最后主动干预。
