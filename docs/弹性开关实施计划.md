# 设置板块「弹性开关」实施计划

> 目标：将「设置」板块内全部持久化设置开关，由原生 `<input type="checkbox">` 统一改造为
> **弹性开关**——滑块按下（拖动起步）时先横向拉伸，松开落位后回弹至原宽，呈现「有质量」的视觉手感。
> 约束：仅改动设置板块内的开关，不影响其他任何功能。

- 文档版本：v1.0
- 创建日期：2026-08-23
- 适用仓库：`wxnn-photo-manager`（无限暖暖相册管理工具，Electron + Vite + React）

### 2.2 动画技术选型：纯 CSS，**不引入 Framer Motion**

仓库虽已安装 `motion`（Framer Motion v12），但 **本次刻意不使用**，理由为遵循项目既有硬约定：

`src/renderer/styles/globals.css` 第 507-509 行原文注释：

```
/* P0-2：motion.button → 原生 button 的 hover/active 微交互类
   替代 whileHover/whileTap 的 spring 缩放，使用 cubic-bezier 接近 Fluent Design 连接动画。
   compositor 线程处理 transform，不影响 React 渲染，避免 React 19 props 泄漏 DOM 警告。 */
```

即项目**已明确要求交互态（hover/active）微动画走 CSS 类而非 motion 的 `whileTap`**。三条支撑理由：

1. **性能**：`transform` 由 compositor 线程合成，不触发 React 重渲染。
2. **规避 React 19 props 泄漏 DOM 警告**（该注释显式点明）。
3. **可测试性**：`tests/setup.ts` 第 125-201 行全局 mock 了 `motion/react`，会剥离
   `whileTap` / `animate` / `transition` 等 props。若用 motion 实现，动画意图在 jsdom 下
   **完全不可断言**；而 CSS 类名可被单测直接断言。

> 结论：选择 CSS 属于**复用项目既有成熟方案**（沿用 `.motion-hover-scale-*` 同族命名与写法），
> 而非「从零自写」。新增 CSS 约 40 行，新增 TSX 约 50 行，符合「尽量精简、复用现有代码」的要求。

## 4. 组件设计

### 4.1 DOM 结构

```
<div>                                   ← 行容器
  ├── <div flex items-center justify-between>
  │     ├── <div>                       ← 文案区
  │     │     ├── <div id={labelId}>    ← 可见标签
  │     │     └── <p id={descId}>       ← 可选描述（存在时才渲染）
  │     └── <button role="switch"        ← 开关本体
  │              aria-checked
  │              aria-labelledby={labelId}
  │              aria-describedby={descId}
  │              disabled
  │              class="settings-elastic-switch">
  │           └── <span class="settings-elastic-switch-knob" />   ← 滑块
```

关键点：

- 用 `<button>` 而非 `<input type="checkbox">`：原生支持 `Space` / `Enter` 键盘切换与 `:active` 伪类。
- **不再用 `<label>` 包裹**：`role="switch"` 的按钮通过 `aria-labelledby` 关联可见文案，
  避免 `<label>` 内嵌 `<button>` 时点击事件双触发的隐患。
- 描述文案通过 `aria-describedby` 关联，读屏可播报。

### 4.2 参数契约（`SettingsToggleProps`）

```ts
export interface SettingsToggleProps {
  /** 可见标签文本（必填、非空；用于 aria-labelledby 关联） */
  label: string
  /** 可选描述文案；提供时渲染并通过 aria-describedby 关联 */
  description?: string
  /** 受控开关状态；非 boolean 时按 falsy 归一化处理 */
  checked: boolean
  /** 切换回调，接收「取反后」的新值；组件内部已做异常兜底 */
  onChange: (checked: boolean) => void
  /** 禁用态：短路 onChange、置 aria-disabled、降低不透明度、不可点击 */
  disabled?: boolean
}
```

**保持向后兼容**：props 名称与语义与改造前的 `SettingsToggle`（`shared.tsx:139-150`）完全一致，
仅内部渲染实现改变，故不影响任何潜在外部调用方。

### 4.3 CSS 弹性动效实现要点

新增三个类（置于 `globals.css` 的 `.motion-hover-scale-*` 之后，保持同族聚拢）：

| 类名                                | 职责                                                                    |
| ----------------------------------- | ----------------------------------------------------------------------- |
| `.settings-elastic-switch`          | 44×24 胶囊轨道；`position: relative`；背景/描边随 `[aria-checked]` 切换 |
| `.settings-elastic-switch-knob`     | 18px 白色圆形滑块；`position: absolute`；承载位移与拉伸动画             |
| `.settings-elastic-switch:disabled` | `opacity: .5` + `cursor: not-allowed` + `pointer-events: none`          |

**弹性手感的核心三行**：

```css
.settings-elastic-switch-knob {
  transition:
    left 260ms cubic-bezier(0.34, 1.56, 0.64, 1),
    transform 260ms cubic-bezier(0.34, 1.56, 0.64, 1);
  transform-origin: left center; /* 关闭态向右生长 */
}
.settings-elastic-switch:active:not(:disabled) .settings-elastic-switch-knob {
  transform: scaleX(1.35); /* 按下：横向拉伸 */
}
```

- `cubic-bezier(0.34, 1.56, 0.64, 1)` 的控制点 y 值 `1.56 > 1`，产生**过冲后回落**，
  即松开时 `scaleX` 从 1.35 掠过 1 以下再稳定到 1，形成「有质量」的回弹。
- `transform-origin` 需随开关态翻转：关闭态 `left center`（向右拉伸），
  开启态 `right center`（向左拉伸），使拉伸始终朝向轨道内侧、不溢出轨道。

### 4.4 动效减弱（`html.reduce-motion`）挂接

`globals.css:151-158` 的通配规则已把 `transition-duration` 压到 `0.01ms`，但**不足够**——
`transform: scaleX(1.35)` 仍会瞬时生效（只是没有过渡）。因此必须在
`globals.css:181-196` 既有的 `transform: none !important` 列表中**追加**：

```css
html.reduce-motion .settings-elastic-switch:active .settings-elastic-switch-knob
```

与 `.motion-hover-scale-*:active` 的处理方式完全一致。

> 该项自带回归验证价值：开关 #8（`reduceMotion`）本身就控制 `html.reduce-motion` 类，
> 开启它后其自身的弹性动效应立即失效——可在开发态一键自验。

## 5. 错误处理

| 场景                                | 处理策略                                                                                                         | 落点                                 |
| ----------------------------------- | ---------------------------------------------------------------------------------------------------------------- | ------------------------------------ |
| `onChange` 回调抛出同步异常         | 组件内 `try/catch` 捕获，`console.error` 输出，**不向上冒泡**，保证设置页其余部分不被 React 错误边界卸载         | `SettingsToggle` 内部 `handleToggle` |
| `onChange` 未传 / 非函数            | `typeof onChange !== 'function'` 时短路返回并 `console.error`，避免 `TypeError: onChange is not a function`      | 同上                                 |
| `disabled` 态被程序化点击           | `handleToggle` 首行短路 + 原生 `disabled` 属性双重保险                                                           | 同上                                 |
| 持久化失败（`settings.set` reject） | **沿用各 section 既有通路**：`updateSetting` 已 `await`，异常由既有 Toast（`showMessage`）反馈。本次不改动该逻辑 | 各 `*-sections.tsx`                  |
| `label` 为空 / 非字符串             | `console.error` 警告（无障碍缺陷），但仍渲染开关，不阻断页面                                                     | 同上                                 |

> 说明：项目 React 指南中有「不要用 try catch，应 console.error」的表述，其意图是**避免静默吞异常**。
> 此处的 `try/catch` **同时 `console.error`**，属于「错误隔离 + 显式上报」，符合该意图；
> 且用户需求明确要求「错误处理」章节，故保留此兜底。

## 6. 参数校验

采用**运行时防御 + 编译期类型**双层校验：

| 参数          | 编译期（TS）                | 运行时校验                                      | 失败行为                                                        |
| ------------- | --------------------------- | ----------------------------------------------- | --------------------------------------------------------------- |
| `label`       | `string` 必填               | `typeof label === 'string' && label.length > 0` | `console.error`，仍渲染                                         |
| `checked`     | `boolean` 必填              | `Boolean(checked)` 归一化                       | 非 boolean 按真值性折叠，`aria-checked` 恒为 `"true"`/`"false"` |
| `onChange`    | `(c: boolean) => void` 必填 | `typeof onChange === 'function'`                | `console.error` + 短路，不触发                                  |
| `description` | `string \| undefined`       | 真值判断后才渲染 `<p>`                          | 缺失时不渲染描述节点、不生成 `aria-describedby`                 |
| `disabled`    | `boolean \| undefined`      | `Boolean(disabled)`                             | 短路 `onChange`                                                 |

**关键不变量**：`aria-checked` 必须始终是字符串 `"true"` 或 `"false"`（不得为 `undefined`），
否则读屏无法播报开关态。由 `Boolean(checked)` 归一化保证。
